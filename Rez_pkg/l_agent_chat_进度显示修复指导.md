# l_agent_chat 进度显示修复指导

## 1. 目标与范围

修复“长时间只显示规划中”“正在收内容却显示无新进度”“等待用户被误认为模型卡住”等问题。

本文只给修复指导，不执行业务代码修改、构建、服务启停或部署。此前修复任务被中止，可能已有部分代码落盘；实施时必须以当前源码为准，不能按旧报告整段重写。

约束：

- 只修进度生产、转发、显示与测试，不改提示词、工具调度或流程图。
- 不用心跳冒充模型思考，不给虚假百分比。
- 上游不吐内容时，只能显示等待或内容静默，不能断言它正在思考或已经卡死。
- 模型生成工具参数不等于工具已经执行。
- 默认只留本机；公网部署另行确认。

## 3. 统一进度语义

必须分开三个概念：

1. **运行总耗时**：整轮开始到现在。
2. **阶段耗时**：本次模型请求、工具执行或用户等待开始到现在。
3. **内容静默时间**：距最近真实模型内容到达多久。

SSE 注释 ping 只用于保活；role、usage、空 delta 等协议帧不算真实内容。

建议沿用现有 status 字段，不另起第二套协议：

| 字段 | 定义 |
|---|---|
| `phase` | `waiting`、`received`、`reasoning`、`response`、`tool_args`；工具与用户等待补明确阶段并统一前后端取值 |
| `received` | 本事件是否包含真实内容进展；不代表连接在线，也不代表每次 status 都有进展 |
| `elapsed` | 当前模型请求耗时，单位秒；不要与前端 run-process 的整轮毫秒耗时混用 |
| `silent_seconds` | 距真实内容到达的时间；无内容时从本次请求开始计 |
| `first_data_seconds` | 明确口径。当前 `_progress_status` 在首次 `model_progress` 时设置，实际上是首次内容耗时，不是 TCP 首字节 |
| `reasoning_chars` | 本次请求累计推理内容字符数 |
| `response_chars` | 本次请求累计回复字符数 |
| `tool_args_chars` | 本次请求累计工具参数字符数 |
| `data_events` | 本次请求真实内容事件数 |
| `key` | 同一次阶段的稳定标识；原地更新，不把每个心跳追加成一步 |

如要展示“协议首包”和“首个内容”两个时间，必须增加明确区分的字段，不能把同一个 `first_data_seconds` 在不同路径下解释成两件事。

## 4. 子任务 A：前端显示与计时

范围：

- `rez-package-source/l_agent_chat/999.0/web/src/new/NewApp.jsx`：`RunProcess`。
- `rez-package-source/l_agent_chat/999.0/web/src/new/runtime.js`：`stepData` 与事件消费。

实施步骤：

1. `RunProcess` 读取 `data.progress`，当前状态优先取其 `text`，缺字段时才回退历史步骤文本。
2. 总耗时用整轮 elapsed 的采样值加采样后的本地时间差；不能拿内容静默时间给总耗时续表。
3. 模型内容静默由服务端 `silent_seconds` 映射为本地基准，再随时间增长；心跳更新说明，但不能重置该基准。
4. 收到 reasoning/delta 时刷新真实内容时间，即使步骤数量、key、t 都没变。
5. `runtime.js` 当前 reasoning/delta 分支整体替换 progress，会丢 phase 和计数。按事件语义保留或更新有效字段，避免下一帧把遥测抹掉。
6. 工具开始、结束、审批、ask_user、multi_ai 确认、收尾、异常、停止时，明确转换阶段，不能沿用上一请求的 waiting 或计数。
7. 等待用户时显示“等待你批准/回答/确认”；不得显示“模型无新进度”。工具执行没有新事件时显示“工具执行中，暂无新输出”，不推断挂死。
8. 历史完成消息不启动态计时；重连回放不得把旧内容当成刚刚到达而重置静默时间。

验收：模型持续输出 20 秒且始终同一步，不能出现“20s 无新进度”；总耗时持续递增，内容到达不使总耗时跳回或重复累加。

## 5. 子任务 B：后端规划与作答链路

范围：

- `rez-package-source/l_agent_chat/999.0/src/l_agent_chat/app.py`。
- `rez-package-source/l_agent_chat/999.0/src/l_agent_chat/agent_client.py`。

先核对已经落盘的实现，不重复新增同功能辅助函数。

实施步骤：

1. 主规划、复述重试都走相同进度通道；每次真正的新请求重置请求计时和累计计数。
2. 工作线程 callback 到达后即时唤醒异步消费；不能等整个调用结束才一次性排出进度。
3. 保活循环让出事件循环，不在 async 主循环直接执行同步网络读取。
4. 流式作答、非流式作答、JSON 回退、空响应降级、内联工具后的续答全部核对。
5. 非流式响应返回前只报等待，返回完整 JSON 后才报内容；不能伪造中途字符增长。
6. `_progress_status` 当前心跳默认回落 waiting；应区分“最后已知内容阶段”与“目前未收到新内容”，避免刚收到推理后两秒又看似重新等首包。
7. 若底层一次调用内自动重试，需通知上层新的请求开始；否则累计计数和首内容耗时会串台。可在现有回调里增加请求边界语义，保持不传回调的旧调用行为不变。
8. usage、空 delta、协议 role 帧不得刷新真实内容时间；异常与取消必须收敛，不继续显示正在运行。
9. 中断轮询不等于阻塞网络读立即取消。检查既有请求超时和关闭语义，明确记录仍存在的取消延迟，不虚报停止完成。

验收：先等首内容 8 秒，再连续推理、输出参数、执行工具；界面每个阶段准确，参数接收阶段不显示工具已执行。重试从新的请求计时，不继承旧静默时长。

## 6. 子任务 C：审批与其他等待

范围：`app.py` 的审批、ask_user、multi_ai 确认等待分支及前端对应事件。

实施步骤：

1. 审批等待已出现 ping 代码，检查实际每个周期发出 SSE 注释保活，不只更新内部变量。
2. `asyncio.wait_for` 的分片超时不能取消共享 future；沿用 shield 或其他既有安全等待方式。
3. 超时预算使用阶段起点计算，防止每个分片重置预算导致无限等待。
4. 停止与拒绝分别收敛到正确状态；等待期间的停止不要求用户先回答。
5. 等待用户阶段采用独立计时，既不算模型思考也不算工具真实执行耗时。
6. ask_user、multi_ai 确认与审批核对相同保活原则；不要因审批修好了就宣称所有等待分支都覆盖。

验收：缩短测试保活周期，验证用户不操作时收到 ping；随后点击停止或批准，等待 future 未被分片超时误取消，运行正常结束或继续。

## 7. 子任务 D：验证与交付

### 测试矩阵

| 场景 | 必须断言 |
|---|---|
| 首内容前长等待 | 有真实等待说明，计时变化，没有虚假思考或字符数 |
| 只有 role/usage/空 delta | 可记录协议活动，但内容计数与内容静默基准不变 |
| 同一步持续推理/回复 | 计数增长，不误报模型停滞 |
| 工具参数分片 | 显示接收参数，工具尚未执行 |
| 工具长执行 | 工具卡计时，阶段准确，未输出不等于卡死 |
| 非流式/JSON 回退 | 返回前仅等待，完整结果到达后更新 |
| 降级/复述重试/续答 | 请求计时与累计计数按边界重置 |
| 审批/ask_user/multi_ai 确认 | 用户等待说明，保活，停止和超时正确 |
| 重连/刷新/历史消息 | 不伪造刚收到内容；完成消息计时停止 |
| 异常/停止/结束 | 无残留 running 阶段，按钮与计时正确收敛 |

### 执行原则

- Rez 包测试通过项目 `wuwo/wuwor`；不用系统 Python 或全局 `rez env`。
- 前端构建使用已存在别名 `l_agent_chat_web_build`；实际入口先核对 package 定义。
- 服务状态先查 `wuwo svc list`，需要单卡时注意 `l_agent_chat` 与开发卡的子串匹配歧义。
- 带热加载的本机服务不盲目重启；隔离浏览器测试不得打断用户当前会话。
- 独立实例按 `rez-package-source/Rez-Docs/Rez_pkg/l_agent_chat_隔离实例A_B实测.md` 的配方执行，先读原文。
- 最后重新读取关键源码，确认修改没有消失；核对构建产物与浏览器实际加载资源，不能只看构建退出码。
- 假 provider 浏览器测试与真实供应商测试分别报告。假 provider 能验证状态机，不能证明真实供应商延迟已经改善。

## 8. 推荐拆分与完成判据

A 前端显示、B 后端模型链路、C 用户等待、D 集成验收，可分四次实施。B 与 C 都修改 `app.py`，必须顺序执行，避免覆盖；A 可独立处理，D 最后执行。

完成必须同时满足：

- 所有模型与用户等待分支都有诚实且连续的状态说明。
- 心跳、协议活动、真实内容三者语义分开。
- 总耗时、阶段耗时、内容静默时间不混用。
- 当前源码、构建产物、浏览器显示一致。
- 测试矩阵有实际结果，未验证边界明确写出。
