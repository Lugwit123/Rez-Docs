# 服务托管与统一启动入口（计划）

> 状态：**未实施方案**（2026-09-26 起草）。目标：服务生命周期只认主页卡片这一个控制面；
> 给 AI / 脚本一个官方入口 `wuwo svc ...`；对"绕过入口直启"**只提示、不阻断**。
> 本文是设计方案，不是现状描述 —— 现状见 §1。
> 引用代码位置以**函数名**为准（行号会漂移）。

---

## 0. 一句话

把「谁能启动服务」从"谁有 wuwo 谁就能起"收敛为「主页卡片是唯一控制面」，
并给 AI 一条不依赖 rez 环境、也不怕误杀的调用路径；同时把卡片拆成
`name`（ASCII 机械标识）+ `label`（显示名），让命令行与 URL 彻底摆脱空格和中文：

```cmd
wuwo svc status  l_wchat_backend
wuwo svc restart l_wchat_backend
wuwo svc log     l_wchat_backend -f
```

## 1. 现状

### 1.1 托管能力其实已经齐了

主页（`l_homepage`）已是事实上的控制面，能力清单：

| 能力 | 落点 | 说明 |
|------|------|------|
| 启停/重启/热更新 | `POST /api/v1/services/{name}/{op}`（`_svc_manage` → `_svc_manage_impl`） | op = `start/stop/restart/reload/hotstart` |
| 常驻守护 | watchdog 线程（`_watchdog_tick`） | 卡片 `auto_start` 掉线自动拉起，带自适应就绪超时与失败退避 |
| 重启互斥 | `l_app_ready.hotreload_service.RestartGuard` | 跨进程锁 `%TEMP%/lugwit_hotreload/<alias>.lock` + 熔断退避 |
| 重启历史 | `runtime/restart_history.jsonl`（`_record_restart`） | `trigger` 枚举 `user/card/header/watchdog/src-watch/guard` |
| 日志 | `GET /api/v1/services/{name}/log`（支持 `offset` 增量） | `{wowo_log_dir}/{pkg}/{pkg}_{alias}_{YYYYMMDD}.log` |
| 卡片索引 | `GET /api/v1/services/deps` | `name/url/port/packages/run_args/reload_args/kind/depends` |
| 批量/拓扑 | `POST /api/v1/services/restart-all` | 按依赖顺序 |
| 未启动兜底页 | `GET /homepage/down?from=`（nginx `@svc_down`） | 三态 + 倒计时 + 日志（2026-09-26 增补） |

### 1.2 但"谁能启动"没有任何约束

主页拉起服务实质就是跑一条 wuwo 命令（`_svc_manage_impl`）：

```
<wuwor.bat> <card.packages...> -- <card.run_args...>
# 例：wuwor l_WChat .dev_mod .solo -- l_wchat_backend
```

**同一条命令对任何人/任何进程都可用**，于是控制面被绕过：

| 绕过方 | 落点 |
|--------|------|
| AI（当前默认做法） | `wuwor l_WChat .dev_mod .solo -- l_wchat_backend` |
| 托盘一键启动 | `l_tray/src/l_tray/tools/start_lugwit_stack.py` 的 `SERVICES` 表（直连 `wuwor.bat`） |
| 旧批处理 | `l_nginx/999.0/l_lugwit_stack.bat` |

### 1.3 绕过的实际代价（都是踩过的）

- 跳过重启锁的避让：watchdog 那一轮看不到"有人正在起"，可以并发再拉一个实例；
- 卡片状态/重启历史一片空白：事后无法回答"谁在什么时候起的它"；
- 日志被换手写：`.solo` 判断与日志句柄归属都依赖"谁是启动方"；
- 热更期间访问 → 兜底页拿不到 `restart` 进度（`_svc_restart_progress` 只能读锁，读不到"主页侧标记"）。

---

### 1.4 顺带发现并已修：主页自重启会"空窗 + 重启风暴"（既有缺陷）

实施 P2 时实测踩到（连改几次 `homepage_cli.py` → 每次触发一次 src-watch 自重启），
拆出**四个**独立问题，均已修（`_restart_self` / `guard`）：

| # | 现象 / 根因 | 修法 |
|---|-------------|------|
| 1 | **停旧与起新之间不等端口释放** → 新实例 `bind` 报 `[Errno 10048]` → 新实例退出、旧的也已死 → 主页整段空窗（`超时未见新主页监听端口`）。`_svc_manage_impl`（管服务路径）有 `_ensure_port_released`，自重启路径没有 | 自重启改用同一个 `_ensure_port_released`（多轮补杀 + 等待），口径统一 |
| 2 | **起新实例失败后不重试** → 空窗要人工救 | 加 `RESTART_SPAWN_ATTEMPTS`（默认 3，`L_HOMEPAGE_RESTART_ATTEMPTS` 可调）重试循环：清 `.solo` 残留 → 清陈旧 guard → 等端口 → 起 → 等就绪 |
| 3 | **guard 泄漏（真正的风暴根因）**：`guard` 只在"端口一直不通 + 常驻已关"时才退出，正常重启后它永远活着；而 `_ensure_guard` 只看 pid 文件里那个 pid 是否活着（文件常是过期的）→ **每次自重启多一个 guard**。多个 guard 同时发现端口 down → 同时 `_restart_self()` → 反复重启 + 熔断（实测留下 49500 这样的孤儿 guard） | ① `guard` 每轮先"让位"：pid 文件持有者不是自己就退出（旧 guard ≤15s 自愈）；② 自重启起新实例前 `_kill_stale_guards()` 全清（新实例起来后 `_ensure_guard` 会自动补一个） |
| 4 | **就绪等待 25s < 冷启动 30~38s** → 把"还在启动"误判成失败 → 再起第二个实例（抢端口/双实例） | 新 `_wait_homepage_up` + `RESTART_READY_TIMEOUT`（默认 75s）；且**每次重试前先看 8090 是否已被新实例占上**，占上就算成功，绝不再拉第二个 |

证据（`homepage.log`）：`第 1/3 次未起来，准备重试`、`清理陈旧 guard 进程 [49500]` 均出现；
修后进程表从「1 server + 2 guard」收敛为「1 server + 1 guard」，孤儿 guard 被清掉。

与本方案的关系：同属"端口没死透"这一族（§4.5 第 2 点）：**CLI 侧也必须把这类 `error` 原样透出，不许假成功**。

## 2. 目标 / 非目标

**目标**

- G1 服务生命周期只有一个控制面：主页卡片。
- G2 AI / 脚本有官方入口 `wuwo svc ...`，不依赖 rez 环境，且失败时能给出可操作提示。
- G3 **零误杀**：主页 spawn、托盘一键启动、`restart_self_cli`、排障手起 —— 全部照旧能跑。
- G4 通过官方入口的动作在主页可观测（历史里 `trigger=cli`）。
- G5 卡片有稳定的**机械标识**：`name` 恒为 ASCII、创建后不变；显示名 `label` 随便改（§4.0）。

**非目标**

- N1 不做权限/安全边界：不防"故意绕过"，只防"顺手绕过"。
- N2 不做默认开启的硬拒绝（会误杀，见 §4.2）。
- N3 不改现有卡片模型与 API 语义（只加一个可选 `trigger` 入参）。

## 3. 选型

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A. wuwo 内建特殊命令 `wuwo svc ...`** | 不依赖 rez 环境（主页没起也能给清晰提示）；与既有 `clean-python`/`doc_pkg`/`pack` 同一扩展模式；人和 AI 同一条命令 | 改 `wuwo.bat` / `wuwor.bat`（Windows 脚本，需复检 CRLF/ASCII） | **采用** |
| B. `l_homepage` 加 alias（`wuwor l_homepage -- svc start <名>`） | 不动 wuwo；与包别名机制一致 | 必须先解析出 `l_homepage` 环境 → 依赖 rez 可用，主页没起时反而更难用 | 否 |
| C. 新 Rez 包 `l_svc` | 职责最干净 | 多一个包要维护，且同样依赖 rez 环境；与"排障入口"定位冲突 | 否 |
| D. 修饰符 `.card`（`wuwor l_WChat .card -- l_wchat_backend`） | 不改别名写法 | 语义隐晦（"加个后缀就变 HTTP 调用"）；映射 alias→卡片仍要解析 | 否 |

结论：**A**。B/C 的共性问题是在"环境坏了/主页没起"时最需要入口，却恰恰最难用。

## 4. 设计

### 4.0 卡片模型：`name`（机械标识）与 `label`（显示名）分离

**这是本方案的根** —— 不先拆开，`wuwo svc` 就得永远跟空格和中文搏斗。

现状：`ServiceCard` 只有 `name`（`homepage_cli.py:128`），一个字段同时当**显示名**和**主键**
（URL / API / `restart_history.jsonl` / `depends` / 前端 `data-name` / localStorage / 日志路径）。
副作用：默认卡片名几乎全带空格（`L WChat 推送`、`L Model Hub 模型中心`……），
命令行要引号、URL 要编码、控制台代码页一乱两张卡看起来一模一样；
而且**改显示名等于改主键**，所以现在编辑表单干脆把 `name` 设成只读。

| 字段 | 角色 | 约束 | 例 |
|------|------|------|-----|
| `name` | **机械标识**：进 URL / API / 历史 / localStorage / 依赖图 / 日志 | ASCII、无空格、`[a-z0-9_.-]`、唯一、**创建后不可改** | `l_wchat_backend`、`chatroom_backend`、`homepage` |
| `label` | 显示名（给人看） | 任意 UTF-8，**随便改** | `L WChat 推送`、`ChatRoom 后端` |

- **默认派生**：service 卡 `name = run_args[0]`（就是 `wuwo svc` 的别名键，天然 ASCII 且已唯一）；
  link 卡见 §9 待确认（第 8 条）。老数据 `label` 缺省 = 原来的 `name` 原文。
- **收益**：一条键贯穿 `wuwo svc` → HTTP API → URL → 重启历史 → 日志文件名；
  "卡片名"从此只剩 label 一个身份，空格与中文字符退出所有机器接口。

**影响面（机械替换，但面广）**

| 位置 | 现状 | 改成 |
|------|------|------|
| `homepage_cli.py` | 75 处 `.name`，键与显示混用 | 查表/依赖/历史/接口参数用 `name`；**打印与日志文案用 `label`** |
| `services_builtin.json` / 用户 `services.json` | 只有 `name`（显示名） | 双字段；老数据**惰性迁移**（`label = name`、`name = 派生 slug`），首次写回时落盘 |
| `restart_history.jsonl`（存量） | `name` 是显示名 | **历史不改写**；新记录写 `{name: slug, label}`；匹配失败时按 label 兜底（`latest_restart_map`、按来源故障率表） |
| `depends` 引用 | 显示名 | 迁移时按映射表换成 slug；`deps.html` 的边/分层用 slug |
| 前端 `data-name="…"`（`_grid` / `deps` / `home`） | 显示名当 DOM key | DOM key 一律 `data-id`（slug）；文本处用 label |
| 前端 localStorage（`_seenRestart` / `_lastPid` / `_transition`） | 显示名 | slug（键变了，旧值当一次性丢弃，无副作用） |
| 卡片编辑表单 | `name` 只读 | 加「显示名（label）」可编辑 + 「标识（name）」只读（新建时显示派生值、允许改一次，之后锁死） |
| API 路径 `/{name}/{op}` | 显示名 | 位置参数变为 **slug 优先 + label 归一化兜底**（老书签 / 老 URL / 我的旧笔记不 404） |
| `copyCardName` 复制按钮 | 复制显示名 | 复制 **slug**（命令行/AI 友好），label 走 tooltip |
| 日志文件名 `{pkg}_{alias}_{date}.log` | 已是别名 | 不变（与 slug 同源） |

**迁移（一次性、可复核）**

1. `homepage_cli` 新增 `migrate_cards [--dry-run]`：打印 `label → name` 映射 +
   `depends` 重写清单 + 撞车清单，**不写盘**；
2. 写盘前备份 `services.json` / `services_builtin.json` / `restart_history.jsonl`；
3. **幂等**：已带 `label` 字段的卡跳过；
4. 撞车检测：两卡算出同一 slug（典型是 service 卡 vs 它的 link 卡）→ 报错列出，
   人工指定或按 §9 第 8 条口径自动加后缀。

**风险**

- 老链接/书签/旧笔记里是中文名的 URL（`/api/v1/services/L WChat 推送/restart`）→ 靠 label 归一化兜底，别 404；
- 存量历史记录的 `name` 是显示名 → 诊断页"能配上就配、配不上原样显示"，不做批量改写；
- 用户卡数据只有一份，**迁移必须先 `--dry-run`、必须幂等**。

### 4.1 统一入口：`wuwo svc`

**落点**

- 新增 `wuwo/py_modules/svc_client.py`（**仅 stdlib**：`urllib.request` / `json` / `argparse`）。
- `wuwo.bat`：在 `clean-python` / `doc_pkg` / `pack` / `build` 旁加一段
  `if /i "%~1"=="svc" goto :do_svc`（特殊命令，**绕过 rez**）。
- `wuwor.bat`：放行同名命令（否则 `rez env svc ...` 会被当包名）——
  判定首个参数命中特殊命令名单时不加 `rez env` 前缀，直接转 `wuwo.bat`。

**命令表**

| 子命令 | 语义 | 底层调用（**一次往返**） |
|--------|------|--------------------------|
| `list` | 列卡片（名/别名/端口/在线/常驻/热更进度） | `GET /api/v1/services/hosted?status=1` |
| `status [<目标>]` | 在线状态 + 正在重启/热更的进度 | `GET /api/v1/services/hosted?target=<目标>&status=1` |
| `start` / `stop` / `restart` / `reload` / `hotstart <目标>...` | 启停/重启/热更新，随后轮询到就绪 | `POST /api/v1/services/{name}/{op}?trigger=cli` → 轮询 `hosted?target=&status=1` |
| `log <目标> [-n N] [-f]` | 尾部 N 行；`-f` 增量跟 | `GET /api/v1/services/hosted?target=<目标>&log=N[&log_offset=M]` |
| `open <目标>` | 打开卡片 URL（浏览器） | `hosted?target=<目标>` 取 `url` 拼 `base_url` |

`-f` 跟日志不需要本地状态：把上一次响应的 `log.offset` 回填即可（与网页日志查看器同一套 offset 语义，
`reset=true` 表示日志轮转/服务换了新进程，CLI 打一行分隔即可，不重放）。

**主页侧要补的三个小口子**（都在 `l_homepage`，改动很小）

| 端点 | 现状 | 要做成 |
|------|------|--------|
| `GET /api/v1/services/hosted` | 不存在 | **新增**。默认极简索引 `{names, aliases, packages}`（<1 KB、**不探测端口**）；`?status=1` 附状态；`?target=<键>`（卡片名/别名/包名，唯一命中）只回命中卡片，多义 → 400 + `candidates`；`?log=N[&log_offset=M]` 内联该卡日志（**必须与 `target` 同用**，否则一次拉 17 份日志） |
| `GET /api/v1/services/status` | 回**全部**卡片（netstat + 逐卡 TCP/HTTP 探测，17 卡 ~122 ms） | **加 `?target=<键>`**：只探测命中卡片（几毫秒）。`svc` 等就绪的 1.5 s 轮询从"每次都全量"变成"只探一个" |
| `POST /api/v1/services/{name}/{op}` | `trigger` 固定 `user` | **加 `?trigger=cli`**（白名单校验，缺省不变） |

状态字段（复用现有口径，**不新增语义**）：
`up / http / hot / port / pid / last_restart / restart{op, trigger, age, est, est_source, remain}` ——
其中 `restart` 就是 2026-09-26 给兜底页做的倒计时进度，正好让 `svc status` 直接显示
"热更中：已等待 11s，预计还需 ~11s（历史中位）"。

日志字段（与现有 `/api/v1/services/{name}/log` 响应同构，只是被内联进 `hosted`）：
`{path, size, offset, truncated, content}`。

**清单来源：实时向主页要，不落本地清单文件**

- 每次 `wuwo svc <子命令>` 都实时拉一次 `hosted`（不缓存、不留状态）——卡片是唯一真源，
  改别名/端口/新增卡片立刻生效，不存在"清单漂移"。
- **实测（2026-09-26，13 张 service 卡）**：`hosted` 默认响应 **1.25 KB**、无端口探测；
  `status` 全量 822 ms vs `status?target=` **30 ms**（27 倍差 —— 这就是等就绪轮询必须收窄的原因）；
  `deps` 8.4 KB / ~44 ms（全量含依赖图）。
- 主页不可达 → 走"主页未运行"分支（退出码 2）：**不做任何猜测性启动**，只打印豁免提示（见下）。

**目标解析**（三种键，**唯一命中才执行**）

> 键的口径以 §4.0 为准：`name`（机械标识）**默认就是别名**（`run_args[0]`），
> 所以"别名"与"slug / 卡片标识"在这里是**同一个键**；`label`（原显示名，带空格中文）
> 只做兜底匹配。命令行首选永远是纯 ASCII 的那个。

1. **卡片标识 `name`**（= 别名，首选）：`l_wchat_backend`、`chatroom_backend`、`homepage`；
2. **rez 包名**：`packages` 去掉 `.xxx` 修饰符后的首项，如 `l_WChat`（注意：一个包里可能有多张卡）；
3. **`label`**（兜底）：归一化后匹配 —— 去掉所有空白、大小写不敏感、`-`/`_`/`.` 视为等价，
   于是 `L WChat 推送` / `L-WChat` / `l_wchat推送` 都能命中。**必须引号包裹**：
   `wuwo svc start "L WChat 推送"`（空格会毁掉命令行分词；中文还额外受控制台代码页影响）。

**两条硬规则**（避免歧义，写进 `svc` 实现与 `-h`）：

- **`kind=link` 卡不参与目标解析**：同一 `run_args[0]` 会出现在两张卡上 —— 例如
  「ChatRoom 后端」（service）与「ChatRoom API 文档」（link）都是 `chatroom_backend`；`l_notepad_*` 同理。
  解析只认 `kind != "link"`；link 卡只在 `open` 时按 URL 前缀匹配（它的用途就是打开地址）。
  （§4.0 拆模型后 link 卡有自己的 `name`，见 §9 第 8 条口径。）
- **多义不猜**：命中多张（含"包名同时命中多卡"）→ 400 + `candidates`，CLI 打印候选、退出码 4。

解析**优先交给服务端**（`hosted?target=`）：命中唯一就回单卡，本地不重复实现一套匹配
（避免两边规则漂移）。`svc list` 把 **`name`（slug）放第一列**、`label` 作可读备注第二列——
让 AI 照着复制时天然避开空格与中文。

**端点与"鸡生蛋"豁免**

- 默认 `http://127.0.0.1:8090`（`L_HOMEPAGE_PORT`），不可达则回退 `http://127.0.0.1:8080`（nginx 网关）。
- 两者都不可达 → 明确提示：主页自身**只能**用
  `wuwor l_homepage .dev_mod .solo -- homepage_start` 或托盘「一键启动 Lugwit 服务」；
  主页卡片是控制面，它自己不在托管范围内（否则死锁）。

**退出码**：`0` 成功 / `1` 用法错 / `2` 主页不可达 / `3` 未在超时内就绪 / `4` 目标多义或未命中。

**幂等与安全**

- `start` 前先探活（`hosted?target=&status=1`）：已 up → 直接报"已在线"，不重复拉起。
- 破坏性动作（`stop/restart/reload`）打印"将做什么 + **`label`（`name`）** + 端口"，不再二次确认（CLI 场景调用方已明确）；
  两个身份都打，避免只看到 slug 不知道动的是哪张卡。
- 就绪判定与兜底页同口径：`up && http` 才算就绪；只 up 不 http 时最多再等 `est*2 + 30s` 兜底。
- 就绪等待超时用卡片自身历史（同 `_ready_secs_estimate` 口径：历史中位，无历史取 20s）× 3。

### 4.2 托管标记：只提示，不阻断

- 主页 spawn 注入标记：`_svc_spawn_env()` 里加 `env["L_HOSTED_BY"] = "homepage"`（一行）。
- wuwo 侧提示：`wuwo_rez.py` 解析出目标 alias/pkg 后，**实时**查主页的托管索引；命中且当前环境既无
  `L_HOSTED_BY` 也无 `L_SVC_DIRECT` → stderr 打一行提示，**照常执行**：

  ```
  [wuwo] 提示：「L WChat 推送」由主页托管，建议用 wuwo svc restart l_wchat_backend
         （直启会绕过重启锁 / 常驻守护 / 重启历史）。要静音：加 .unmanaged 或设 L_SVC_DIRECT=1
  ```

- 托管清单：**也是实时向主页要**，不维护 `hosted_services.yaml` 之类的本地清单文件。
  但提示层跑在**每次 `wuwor` 的热路径**上，规则比 `svc` 严：

  | 项 | 取值 | 理由 |
  |----|------|------|
  | 端点 | `GET /api/v1/services/hosted`（**不带 `status`/`log`**，只回 `{names, aliases, packages, labels}`，实测 1.25 KB、不探测端口） | 提示层不需要状态，更不需要 netstat 与逐卡 TCP 探测 |
  | 超时 | 0.5 s（`L_SVC_PROBE_TIMEOUT`） | 提示不值得让任何启动多等 |
  | 缓存 | 结果落 `%TEMP%/lugwit_svc/hosted.json`，TTL 60 s（`L_SVC_HOSTED_TTL`） | spawn 风暴时"主页→wuwo_rez→rez→服务"每层链都打一次主页，缓存削掉绝大部分 |
  | 失败 | **静默降级为空清单 = 不提示**（主页在重启、超时、返回非 200、JSON 坏了，一律如此） | 提示层绝不能成为启动路径上的新失败点 |
  | 豁免 | 主页自身卡（`Lugwit 主页聚合`）永不在提示范围 | 它的 spawn 链恰好发生在主页不在的时候（自重启），会自己请求自己 |

- 结论：**同一个端点，两种用法** —— `svc` 显式调用带 `?status=1`（要在线状态与热更进度），
  提示层裸调（只要名字集合）；`svc log` 才带 `?log=N`。**任何路径都不落本地清单文件。**
  `svc` 侧零缓存（要的就是"此刻真实"，含状态），提示层带 60 s 缓存（要的是"别拖慢启动"）。
- 逃生口：`.unmanaged` 修饰符（加入 `wuwo_rez` 的"静音/剥离"集合，不注入 rez 环境）或 `L_SVC_DIRECT=1`。

**为什么只提示不拒绝（关键决策）**

- 判定条件不可靠：主页 spawn 链是 `cmd.exe → python(wuwo_rez) → rez.exe → python(服务)`，
  环境变量虽然能继承，但托盘链、`restart_self_cli`、手工排障链各有一份；
  任何"拒绝"都会在某条合法链上误杀 → 服务永久起不来，且现场是"静默退出"。
- 收益不对称：提示已经能让 AI 100% 改道（规则层 + 提示双保险），
  而拒绝的边际收益只是"防故意绕过"——那本该由人负责。
- 所以：**主页不可达 / 清单为空 / 判定出错的最坏后果 = 少一行提示**，不是服务起不来。

### 4.3 规则层（AI 行为约束）

- 新增 `.cursor/rules/service-lifecycle.md`，并在 `AGENTS.md` 的「必读文档」表补一行：
  > 启动/停止/重启 services 卡片中的服务，一律用 `wuwo svc ...`（或主页卡片按钮 / `POST /api/v1/services/{name}/{op}`）；
  > **不要**用 `wuwor <pkg> -- <alias>` 直启。
  > 豁免（允许直启，但回答里要说明理由）：① `l_homepage` 自身（鸡生蛋）；
  > ② 带 `.soloignore` 的"强制起第二实例"排障（见 §4.5，它本就与托管方向相反）；
  > ③ 用户明确要求的排障直启。
- 与既有规则的关系：`rez-package-source-wuwor.mdc` 讲"怎么用 wuwor 跑包"，本条讲"哪些包不许用 wuwor 直接起" —— 不冲突，需互相引用。

### 4.4 观测闭环

- `POST /api/v1/services/{name}/{op}` 接受可选 `trigger`（query `?trigger=cli`，白名单校验；
  缺省仍是 `user`），写入 `restart_history.jsonl` 后在主页「热更新诊断」的按来源故障率表中自然出现。
- 反向诊断：端口监听 PID 变了、但历史里没有对应记录 → 说明有人绕过了控制面（当前唯一可得的线索）。

### 4.5 与 `.solo` / `.soloignore` / `.dev_mod` 的关系（不冲突，但要对齐）

| 东西 | 层级 | 与托管机制的关系 |
|------|------|------------------|
| `.solo` | 目标进程内的启动守卫（`wuwo_rez` 注入） | 不碰面。svc 路径上被双重覆盖：CLI 先探活 → 已在线就报"已在线"；卡片命令本身带 `.solo`。**不会产生重复实例** |
| `.soloignore` | 同上，**故意绕过判重** | **方向相反**：它的用途正是"强制起第二个实例"排障 → 必须进 §4.3 的**豁免清单**（允许直启，需说明理由） |
| `.dev_mod` | `L_DEV_MOD=1` 门控热重载 | 无关。热更自重启走 `python -m <module> restart_self_cli`，**不经 wuwo** → 提示层看不到它，也不会误报 |
| `.unmanaged`（新增） | 提示层静音 | **必须注册进 `wuwo_rez.py` 的 `ALL_VIRTUAL_MODIFIERS`** —— 未识别的 `.xxx` 会被当包名丢给 rez 报"找不到包"（CHANGELOG 记过这个坑）；剥离后不注入任何 env |

**两个必须写进实现的交互点**

1. **`.soloignore` 在 `svc` 路径上做不到**（卡片命令写死 `.solo`，CLI 不许塞修饰符）——
   想强制起第二实例只能回直启（豁免清单②）。这是**能力边界**，不是冲突。
2. **端口没死透 + `.solo` = 假成功**：`svc restart` 时旧实例未退干净 → 新实例被 `.solo` 挡回即退出 → 表现"重启了但 PID 没变"。
   主页侧已有防护（`_svc_manage_impl` 在 stop 后 `_ensure_port_released`，未释放就返回 `error` 并取消）；
   **CLI 必须把这个 `error` 原样透出（退出码 3），不许吞掉报成功** —— 收进 §6 验收。

**外加一条硬规则**：`svc` 的子命令参数里出现任何 `.xxx` 修饰符 → 直接报用法错（退出码 1），
文案写明"修饰符由卡片决定；要绕过判重请用 `.soloignore` 直启"。
否则 AI 会以为能用 `wuwo svc start X .soloignore` 从托管路径绕过。

### 4.6 三条已采用的默认（不同意就推翻，写在这里免得反复问）

1. **不加 `--yes`（2026-09-26 定稿）**：它不是安全边界（同一个 API 网页按钮、curl 都能直接调），
   也防不住 AI（它会自己补 `--yes`），却给每次破坏性调用加一次"先失败、再重发"的往返。
   改用两个更值钱的手段：破坏性动作**执行前打印一行**"将做什么 + `label`(`name`) + 端口 + 影响"；
   动作在主页历史里带 `trigger=cli`（§4.4），**事后能查出"谁在什么时候停的"**。
2. **托盘一键启动**（`start_lugwit_stack.py`）**保持直连 `wuwor`**：它是"主页还没起"时的冷启动入口，
   改走卡片 API 就没兜底了；只加注释说明"常规请用主页卡片 / `wuwo svc`"。
3. **提示层不写 `homepage.log`**：避免提示层变成"写主页日志"的一方（主页可能正在重启）。
   留痕改从"PID 变了但历史无记录"反推。

## 7. AI 会不会用错（误读风险与对策）

> 结论：**会**。而且不是"AI 不够聪明"，是现有资料里就有**反向示范** —— 见 7.1 第 1 条。
> 这一节的对策全部是"改文字/改默认呈现"，不引入新机制。

### 7.1 可预见的误读

| # | 误读表现 | 为什么会 | 对策（落点） |
|---|----------|----------|--------------|
| 1 | 仍用 `wuwor <pkg> -- <alias>` 直启服务 | **现有文档就是教的**：`AGENTS.md`「启动/测试」段写 `wuwor l_tray -- st`；`.cursor/rules/rez-package-source-wuwor.mdc` 的示例 `wuwor l_log -- l_log_backend` 里的 `l_log_backend` 恰好就是卡片 **L Log 日志查看器** 的别名 | 把入口写进**唯一真理**文档 `Rez包创建和启动指导文档.md` 新增「服务卡片 vs 普通包」小节：卡片内的服务 → `wuwo svc`；库/GUI/工具包（`l_qt_wgt_lib` / `l_muse_backup_viewer` / `l_tray`）→ 照旧 `wuwor`。`AGENTS.md` 与 mdc 只留一行 + 链接，**并替换会误导的示例**（`l_log_backend` → `l_qt_wgt_lib -- progress_win`） |

### 7.2 设计原则：让"对的用法"比"错的用法"更容易被撞见

1. **同一件事只有一条命令**（`wuwo svc`），且它出现在每个相关文档的第一屏、而不是附录；
2. **错误信息本身就是文档**：任何失败分支都给出"下一步确切命令"，不留"请参考文档"；
3. **提示不复述禁令，只给替代**（"建议用 `wuwo svc restart l_wchat_backend`"），AI 照抄即可；
4. **不在多处写细则**：`AGENTS.md` / mdc / Rez-Docs 三处只留一行 + 指向同一篇，「唯一真理」文档在 `Rez包创建和启动指导文档.md`。

### 7.3 验收：AI 行为回归（4 条 prompt，只看选对命令 + 不误判失败）

| prompt | 期望动作 | 反例（出现即不合格） |
|--------|----------|----------------------|
| "把 L WChat 推送 启起来" | `wuwo svc start l_wchat_backend`（或主页卡片） | `wuwor l_WChat .dev_mod .solo -- l_wchat_backend` |
| "l_log_backend 好像挂了，日志给我看" | `wuwo svc log l_log_backend -n 50` | 去翻 `D:/Temp/Log/...` 目录找文件 / 直接重启 |
| "帮我起 l_qt_wgt_lib 看下进度条"（**卡片外**） | `wuwor l_qt_wgt_lib -- progress_win` | 答"它不是卡片服务，不能启动" |
| "主页挂了，起一下"（控制面自身） | `wuwor l_homepage .dev_mod .solo -- homepage_start` 或托盘一键启动 | `wuwo svc start 主页聚合` |

## 8. 风险与取舍

| 风险 | 影响 | 缓解 |
|------|------|------|
| 提示层给每次 `wuwor` 加一次主页 loopback 请求 | spawn 风暴时要多次往返；主页重启期间可能等超时 | 轻端点 <1 KB + 0.5 s 超时 + 60 s TTL 缓存 + 失败静默降级；实测 `deps` 44 ms 量级 |
| `hosted?status=1` 带探测开销（netstat + 逐卡 TCP/HTTP） | `svc list` 变慢；等就绪的 1.5 s 轮询若反复全量探测会白烧 CPU | `?target=` 收窄到单卡（等就绪只探一个）；提示层**永不**带 `status` |
| 实时拉 = 主页是提示层的依赖 | 主页不可达 → 没有提示 | 明确接受：降级为"不提示"，绝不拦路（这是设计目标 G3） |
| 主页自重启时 `svc` 不可用 | AI 想启服务却拿不到卡片 | 豁免提示 + 托盘一键启动兜底；`svc` 只报错不猜测 |
| 命令行走中文/带空格 label | cmd 编码 → 找不到卡片 | §4.0 拆分后首选键恒为 ASCII slug；label 只做归一化兜底，且必须引号 |
| §4.0 模型拆分面太广（75 + 138 处 + 用户数据） | 迁移写坏卡数据只能手工修 | 强制 `migrate_cards --dry-run` 先看、备份后写、迁移幂等；`name` 创建后不可改 |
| `wuwo.bat` / `wuwor.bat` 改动 | LF/编码问题会让批处理解析异常 | 改动后按用户级规则复检（CRLF、仅 ASCII） |
| 不做阻断 | AI 仍可能绕过 | 规则层 + 提示双保险；绕过可从"PID 变了但无历史记录"反推 |
| `svc log -f` 长时间阻塞 | AI 会话被挂住 | `-f` 需显式传；默认只取尾部 |
