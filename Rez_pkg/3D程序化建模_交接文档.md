## 1. 已完成

### 1.1 值契约（`MESH` 端口流的东西）

```python
{"kind":"mesh","format":"mesh3d/2",
 "vertices":[[x,y,z],...], "faces":[[i,j,k],...], "name":"",
 "attrs":{"point":{...}, "vertex":{...}, "prim":{...}, "detail":{...}}}
```

- `vertices` 就是 Houdini 的 `P`；面**一律三角化**（扇形）；上限由插件「顶点上限」管（默认 200000 / 面 400000），**超了报错带数量**，不静默截断。
- **属性走值不走端口**（用户口径：Houdini 没有"一个属性一个端点"）。四类：`point`（=顶点数）/ `vertex`（=面角数 3×面数）/ `prim`（=面数）/ `detail`（1 个值）。长度对不上**直接报错**。
- 兼容入参：本 dict / `(顶点表, 面表)` 二元组 / `.vertices+.faces` 鸭子对象 / 纯顶点表（点云）。所以 `ShapeSurface` 那类老节点能直接接进来。
- `mesh3d/1` 是旧的（只有几何），`mesh3d/2` 才有属性 —— **按用户要求不兼容老图**，老缓存里的 v1 值仍能被 `mesh_of()` 读（没有属性而已）。

### 1.6 GPU（可选后端 torch / cupy，2026-10-21，**已实测**）

用户口径：「建模功能作为插件存在，插件可以重依赖」→ GPU 依赖挂在**插件层**，宿主 `requires` 里不出现 torch/cupy。

- **模块** `l_node_engine/mesh3d_gpu.py`：`configure(mode, minimum, backend)` / `backend_for(元素数)` / `xp()` / `to_numpy()` / `status()` / `summary()`。
  判定顺序：`off` → numpy；元素数 < 门槛 → numpy；**torch 优先**、其次 cupy；都没有 → numpy（原因写进 `status()`，不装死）。
  ⚠ 两个后端都带**冒烟自检**（真跑一个小 kernel）：`import` 成功 ≠ 能算，自检失败就永久回落 numpy（图不会跑到一半炸）。
- **插件字段**：`gpu`（`off`/`auto`/`on`）、`gpu_backend`（`auto`/`torch`/`cupy`）、`gpu_min`（元素数门槛，默认 **200000**）；`status().gpu` 里看得见后端/设备/失败原因。
- **装法（本机已就这么配好了）**：把带 torch 的目录填进插件「依赖目录」——
  `e:\lugwit_rez\rez-package-3rd\torch\2.8.0.cu128\python`（就是 comfy 那份 `torch 2.8.0+cu128`，**预编译 kernel，只要驱动**）。
  另有一个 `C:\Users\<用户>\.lugwit\main\l_node_engine\mesh_deps`（`manifold3d` + 试装的 cupy）。
- **实测（RTX 4080，`l_node_engine_mesh3d_gpu_bench`）**：

  | 用例 | numpy | torch(GPU) | 加速 |
  |---|---|---|---|
  | `taubin` 4 遍 · **65 282 顶点 / 130 560 面** | 462.5 ms | **95.7 ms** | **4.8×**（结果一致，atol 1e-9） |
  | `remesh` 96³（同一网格） | 7966 ms | 7907 ms | 1.01×（瓶颈是**逐三角形栅格化的 python 循环**，不在体素泛洪） |
  | 门槛扫描（taubin，114→1986 顶点） | — | — | 114v 0.46× / 266v 0.88× / **482v 1.64×** / 1106v 1.96× / 1986v 3.04× |

  ⇒ 交叉点在 **300–500 顶点**（taubin）；默认门槛 200000 是**保守取法**（remesh 按体素格数算、且避免 CUDA 上下文反复初始化）。
- **cupy 这条路在本机走不通（如实记）**：只装 `cupy-cuda12x` 时每个 kernel 报 `Failed to find CUDA headers`；
  再装 `[ctk]`（1.6 GB：cublas/nvrtc/cudart/…）和 `nvidia-cuda-nvcc-cu12` 仍报（pip 的 include 树没有 `crt/`，`cuda-pathfinder` 也定位不到）。
  ⇒ 没有系统 CUDA toolkit 的机器**用 torch**；cupy 留给装了真 toolkit 的机器（代码路径保留）。
- **⚠ 两条实话**：① 插件跑在**宿主进程**里，后端一旦加载就常驻（CUDA 上下文 + 显存）；② 现在只有 `taubin` 与 `remesh` 的泛洪/膨胀走 GPU，
  其余算子（图元/细分/置换/雕刻/倒角/UV/散布）仍 numpy —— 它们几万顶点时上传比算还贵。

#### 1.6b CPU JIT（numba `@njit`，2026-10-21 —— 治 `remesh` 的真瓶颈）

`remesh` 慢在**逐三角形栅格化**（GPU 帮不上：那是 python 循环 + 每面一次 numpy 调用）。换成 `@njit` 融合循环：

| 用例（9k 面球） | numpy 版 | numba `@njit` | 加速 |
|---|---|---|---|
| 栅格化 48³ | 658 ms | **2 ms** | **426×** |
| 栅格化 64³ | 815 ms | **1 ms** | **560×** |
| **整个 `remesh` 64³**（预热后） | 608 ms | **328 ms** | **1.85×** |
| 6 邻域泛洪 | 43 ms | 50 ms | 0.9× ⇒ **这块不动**（numpy 切片已最优） |

- 模块 `l_node_engine/mesh3d_njit.py`：`configure(mode, minimum)` / `available(面数)` / `raster(tri, origin, h, dims)` / `status()` / `summary()`；
  用不了 JIT 时 `raster()` 回 `None`，`remesh` 走 numpy 版（**语义完全一致**：floor 后 clip，测试里逐格对拍）。
- 开关：插件字段 `numba`（`auto`/`off`/`on`）+ 环境变量 `MESH3D_NUMBA` / `MESH3D_NUMBA_MIN`（面数门槛，默认 256）；
  `detail.remesh` 里带 `jit: true/false`，一眼看得出这一轮走没走 JIT。
- `cache=True`：编好的机器码落 `__pycache__`，第二次起"每进程首调"几乎零成本（首次约 1 s，别把它算进性能）。
- **numba.cuda 的结论（测过，不通）**：`numba.cuda.is_available()` 原为 False（缺 libNVVM）；装 `numba-cuda 0.30.4` + `nvidia-nvvm`、
  手工拼出 `CUDA_HOME=<deps>\cuda13`（`nvvm/bin` + `nvvm/libdevice`）后**能变 True、认得出 cc 8.9**，但编译报
  `No supported GPU compute capabilities found`（numba 0.68 与 pip 的 libNVVM 13.4 不匹配）；换 `NUMBA_CUDA_USE_NVIDIA_BINDING=1`
  又被 deps 里 `cuda-toolkit` 的 `cuda/` 命名空间挡住。⇒ **GPU 走 torch，numba 只用 CPU**。

#### 1.6c 三方实测对比（numpy CPU / numba CPU / torch GPU，同一台 RTX 4080 机器）

| 用例 | numpy | numba `@njit` | torch（GPU） | 谁赢 |
|---|---|---|---|---|
| `taubin` 4 遍 · 32 514 顶点 / 390 144 半边 | 175–195 ms | **4.5 ms（39–43×）** | 40–45 ms（4.3×） | **numba**（比 GPU 还快 9×） |
| `taubin` 4 遍 · 45 826 顶点 / 549 888 半边 | 245–282 ms | **6.8–7.2 ms（36–39×）** | 56–71 ms（4×） | **numba** |
| `taubin` 端到端（走 `m.taubin`，含打包） | 194 ms | **40 ms（4.8×）** | — | kernel 只 4.5 ms ⇒ **剩下 36 ms 是 `new_mesh` 的 `.tolist()` 打包** |

| 三角形栅格化（9k 面，48/64³） | 658 / 815 ms | **2 / 1 ms（426–560×）** | 没写（不划算） | **numba** |

**分工结论（写进代码的顺序）**：
- `taubin`：**numba → GPU → numpy**（CPU JIT 在 3–5 万顶点比 GPU 快一个数量级；GPU 留给 numba 不可用的机器）；
- `remesh` 的**栅格化**：numba（串行小循环，GPU 化只会把时间花在启动上）；
- `remesh` 的**泛洪/膨胀**：**numpy 切片最优**（numba 慢 6×、GPU 无优势），GPU 只在体素网格特别大时才用；
- 已知瓶颈：**每节点出口 `new_mesh` 的 `.tolist()`**（3 万顶点 ≈ 36 ms）—— 下一步该做"内部保持 numpy、只在需要时转 list"，而不是继续换后端。

## 3. 改这块之前必读的坑

1. **`np.tile` vs `np.repeat`**：Catmull-Clark 的 `he_face` 必须是 `np.tile(np.arange(n_f), 3)`。写成 `repeat` → 边点飞到另一侧、体积腰斩（排查了两轮）。
2. **面绕向**：拼出来的网格常有相邻面同向 → 布尔直接 `NotManifold`、法线出亮带。走 `orient_consistent()`，别绕过。
3. **图元是"未焊接"的**（每面独立顶点）：挤出/布尔/CC 前必须 `weld`（这些节点的默认 `weld=True` 就是这么来的）。
4. **挤出侧壁绕向**必须是 `(a, b, b')`，反过来体积变 0.83 而不是 1.5。
5. **`_band_faces` 只适合"按高度分带"**：扫掠那种任意方向的环，要就地生成三角带，别复用。
6. **`_point_colors` / 顶点色**：HDR 环境光会把 `Cd` 洗白 → `environmentIntensity` 调到 0.35；否则竹编/狮子的颜色看着"发青"。
7. **`canvas=0` 不是坏了**：节点少时编辑器走 ReactFlow/DOM 后端，画布没有 `<canvas>`。别据此判断渲染失败。
8. **3D 标签页可能被"删过"**：布局墓碑在 `layout.closed`（`__layout__.json`），删掉的标签不会自己回来 —— 用面板 `＋` 菜单叫回。
9. **会话 401**：所有写接口要 `lugwit` 令牌；本机 `admin01/666`（`POST 127.0.0.1:1027/api/v1/auth/login`），Playwright 里要把 cookie 注进 context 才能跑端点验证。
10. **跑 Python 只走 `wuwor`**；服务走 `wuwo svc`。直调解释器得到的结论无效。
