# 流程图智能体（图驱动控制流）

> 面向 AI 助手与人的**单一权威文档**：默认智能体（`l_agent_chat`）的**控制流由一张流程图决定**，
> 图由 `l_mindmap_mmd`（:8110）可视化编辑。2026-10-04 落地并实测通过。
> 相关：`Rez_pkg/l_mindmap_mmd.md`（编辑器本包）、`l_agent_chat使用指南.md`（智能体总览）。

## 1. 一句话与边界

- **图决定「路由」**：`branch_calls`（去执行工具 / 走收尾路由）、`branch_steps`（继续 plan / 收尾）、
  `branch_goal` + 四道护栏门（`stall/verify/fact/confirm`，顺序与去向）、`sub`（子图嵌套）。
- **执行仍在 app**：`plan`（一次 LLM 往返）与 `tools`（审批/流式/痕迹）由 `app.py` 步循环**托管执行**，
  引擎侧没给它们注册 handler。所以图不是"通用的 agent 引擎"，而是**控制流层**。
- 图写坏 / 名字拼错 / 引擎报错 → **逐级降级**：全流程 → 只驱动收尾路由 → 纯硬编码，并打 `⚠️`。

## 2. 三档开关（可切换，默认见括号）

| 键 | 默认 | 含义 |
|---|---|---|
| `flow_enabled` | `1` | 关 = **纯硬编码**（完全不读图） |
| `flow_full` | `0` | 开 = **图驱动全流程**（迭代决策也由图定）；关 = 只驱动"无调用收尾路由" |
| `flow_name` | 空 | 用哪张图；空 = 用**智能体名**（当前 `default_intelligent_agent`） |

**档位也可以是「智能体属性」**（2026-10-04）：`agents/<名>.json` 里的

```json
{"name": "default_intelligent_agent", "flow": {"enabled": true, "full": true, "name": "default_intelligent_agent"}}
```

- **解析顺序**：智能体 `flow.*` → 全局 `flow_*` → 图名再空就用智能体名。实现见
  `app.py:_agent_flow_cfg()`；`GET /api/flow/status?agent_name=<名>` 会回 `agent_flow` 原样字段。
- 于是「一个智能体 = 一套控制流」：`default` 不写 `flow` → 跟全局；脑图智能体写死自己的图与档位
  （实测：全局 `flow_full=0` 时它仍 `mode=full, source_kind=user`）。
- 改法：设置页「🧠 智能体与技能接线」（暂未暴露 `flow` 编辑项 → 用 API/手写 json）
  或 `POST :1250/api/agents`（body 带 `flow` 字段，`agents.py:_norm_flow` 只认
  `enabled/full/name` 三个键，类型不对就丢）。
- 全局三档改法：agent 设置页 / `POST :1250/api/settings` `{"settings":{...}}` / 工作区
  `<数据根>/l_agent_chat/.l_agent_ws/settings.json`（watcher 2s 内热生效，无需重启）。

## 3. 图在哪、怎么看

- **文件**：`<LUGWIT_DATA_ROOT>/l_agent_chat/flows/<名字>.json`
  （用户目录优先 → 包内置 `l_agent_chat/.../flows/default.json` 兜底）。
- **编辑器**：`http://127.0.0.1:8080/mindmap-mmd/flow/<名字>`（直连 `:8110/flow/<名字>`）。
  改完点保存即生效；`sub` 节点在「添加 → sub」里放，属性面板选子图。
- **权威状态**：`GET http://127.0.0.1:1250/api/flow/status`
  → `mode=full|routing|hardcoded|off`、`loaded`、`source` + `source_kind=user|bundled`、
  `resolve_name`、`no_calls_start`、`flow_full_active`、`reason`。
  编辑器右侧「智能体驱动就绪度」同时显示**本地近似**与这条**权威值**（含"当前跑的其实不是这张图"提示）。

## 4. 运行轨迹（A1：热力 + 回放）

- agent 每轮把轨迹追加到 `<flows 目录>/_traces/<图名>.jsonl`（只留最近 200 轮）：
  `{ts, mode, steps, end, dur, seq, segs, guards}`；`segs` 是每次 `run_flow` 的分段（算边热力**必须**分段，
  否则段间拼接会造出不存在的边）。
- 编辑器工具条 `📈 轨迹`：图上节点/边热力徽标 + 逐轮回放（轮次/步进/元信息）+ 刷新/清空。
  接口：`GET|DELETE /api/flow-traces/{name}`（聚合时按 `_flow_edge_set` 只保留图上真实存在的边）。

## 5. 策略包（C4：图 + 观感 + 档位，一键切换）

- 工具条 `📦 导出策略` → `<图名>.preset.json`：
  `{kind:"lugwit-flow-preset", version, exported_at, flow, edgePrefs, agent:{flow_enabled, flow_full, flow_name}}`。
- 导入：`📥 导入策略` 或**把文件拖到画布上** → 写回流程图 + 应用观感设置 +
  （agent 可达时）应用档位；agent 不可达只跳过档位并如实提示。
- agent 接口：同源 `/agent_chat/api/*` 优先，退本机 `:1250`。

## 6. 编写图时的硬约束（编辑器 + 服务端会拦）

- **`branch_calls` 必须有 `has_calls` 分支、`branch_steps` 必须有 `steps_exhausted` 分支**，否则只能驱动收尾路由。
- **branch 必须有一条无条件兜底**（末条 `when: always`）；谓词必须是引擎表里的名字（编辑器下拉可查）。
- **gate 的 `guard` 要用已注册名**（`stall/verify/fact/confirm`），写别的 → 运行时回退硬编码。
- 别把 action/branch 指向**装饰节点**（comment/tag/summary）—— 引擎会报"没有下一步"。
- `sub` 不能自指，同调用链不允许重复子图名，嵌套深度 ≤ 8（防环）。
- 保存时的权威校验：`PUT /api/flows/{name}` 会先跑 `l_agent_chat.flow_spec.parse_flow`
  （同 env 直接 import；不同 env 调 `POST :1250/api/flow/validate`，该接口额外查**谓词名**）；
  都不可用 → 跳过（哑存储兜底）。编辑器侧还有一套等价校验挡在保存前。

## 7. 策略诊断与自我复盘（D7）

### 7.1 每轮自动打一行（规则式）
- `l_agent_chat.flow_spec.diagnose(spec, run, flow_full=...)`：规则式给"能落到图上动作"的建议
  （缺结构 / 护栏一轮拦 ≥2 次 → 加 `nudged` 分支 / 步数用尽 → `steps_remain`·`budget_exhausted` /
  goal 模式没用到 `budget_low` / branch_calls 缺兜底）。
- app 每轮结束后按**真实运行数据**打一条 `🔧 策略建议（改图后下一轮生效）：…`（前 2 条），
  并写进过程流水。**只提示，不自动改图**。

### 7.2 按需自我复盘工具 `optimize_agent`（2026-10-04）
**不是每轮自动跑** —— 它是一个普通工具（`l_agent_chat/flow_evolve.py`），三条触发路径：
输入框 `/youhua_agent [重点]`（后端把斜杠展开成明确指令）· 模型自己判断调用 ·
或脚本直接调 `optimize_agent(...)`。

| | |
|---|---|
| 取证三块 | ① `tools`：本轮工具**慢（≥20s）/ 失败 / 反复调用** + 耗时 top ② `flow`：图结构 + 本轮路径 + 护栏触发 + 近 N 轮热点/均步数 + `diagnose` 规则建议 ③ `docs`：本轮知识类工具调用 + **用本轮用户问题反向检索知识库**（有货=本可先查；0 命中=知识缺口） |
| 参数 | `focus=tools|flow|docs|all`、`scope=last|recent5`、`action=report|apply`、`edits`(JSON)、`why` |
| 只读 | `action="report"`（默认）：只出材料，**结论与优化建议由当前这轮的模型自己写**（不额外烧 LLM） |
| 落地 | `action="apply"` + `edits`：`{"flow": 整图}` / `{"note": {kb, rel, text}}` / `{"memory": {file, section, key, text}}`；图改动先过 `parse_flow` + 结构检查（会让全流程驱动降级的**拒收**）→ 备份 `flows/_versions/<图名>/<ts>.json` → 原子写 → 记 `_traces/_applied.jsonl` |
| 数据来源 | `app.py` 每轮结束 `flow_evolve.set_last_run({...})`（同进程，最准）；图/轨迹走 `flow_spec`；知识库走 `notepad_knowledge`（:8765）；记忆走 `memory.upsert` |
| 常驻声明 | 在 `tool_router.CORE_NAMES` 里（否则 `/youhua_agent` 会先绕一次 `find_tools`） |

**红线**：只改**数据**（图 / 笔记 / 记忆），不改引擎与代码；`apply` 走校验+备份+留痕，可回滚。

## 8. 引擎能力一览（写图时可用的积木）

- 节点：`start` · `plan` · `tools` · `branch{cases:[{when,to}]}` · `gate{guard,on_trigger,on_pass}` ·
  `sub{flow,next}` · `end` · 自定义动作（需宿主注入同名 handler）· 装饰 `comment/tag/summary`（执行时忽略）。
- 谓词（25）：`always/true/false`、`has_calls/no_calls`、`wrote_any/not_wrote_any`、
  `verified_any/not_verified_any`、`read_any/not_read_any`、`located_any`、`did_tools/not_did_tools`、
  `goal_mode/not_goal_mode`、`goal_done/goal_unfinished`、`budget_exhausted`、`fail_limit_hit`、
  `steps_exhausted/steps_remain`、`nudged/not_nudged`、`budget_low`。
- 状态（由 app 发布到 `ctx.state`）：`step/max_steps/calls/reason/goal_mode/goal_result/wrote_any/
  verified_any/read_any/located_any/did_tools/fail_limit_hit/budget_exhausted/nudges/goal_seconds/budget_left_s`。

## 9. 排错表

| 现象 | 先看 |
|---|---|
| 图改了不生效 | `GET /api/flow/status` 的 `source_kind`（是不是命中了**包内置**）、`mode`、`reason` |
| 明明开了 `flow_full` 却只走收尾路由 | `reason` 会说缺 `has_calls`/`steps_exhausted`；或引擎报错（过程流水里的 `⚠️`） |
| 这轮为什么没收尾 | 编辑器 `📈 轨迹` 回放该轮；或直接读 `_traces/<图名>.jsonl` 最后一轮 |
| 某道护栏一直拦 | 轨迹里 `guards` 计数；按 `🔧 策略建议` 加 `nudged` 分支 |
| 保存被 400 | 提示就是引擎的原文（未知谓词 / 幽灵引用 / sub 自指…），按提示改 |
| agent 侧档位没生效 | `GET /api/settings` 看 `flow_enabled/flow_full/flow_name` 与 `sources` 层 |
