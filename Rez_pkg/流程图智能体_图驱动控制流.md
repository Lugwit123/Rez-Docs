# 流程图智能体（图驱动控制流）

> 面向 AI 助手与人的**单一权威文档**：默认智能体（`l_agent_chat`）的**控制流由一张流程图决定**，
> 图由 `l_mindmap_mmd`（:8110）可视化编辑。2026-10-04 落地并实测通过。
> 相关：`Rez_pkg/l_mindmap_mmd.md`（编辑器本包）、`l_agent_chat使用指南.md`（智能体总览）。

## 1. 一句话与边界

- **图决定「路由」**：`branch_calls`（去执行工具 / 走收尾路由）、`branch_steps`（继续 plan / 收尾）、
  `branch_goal` + 四道护栏门（`stall/verify/fact/confirm`，顺序与去向）、`sub`（子图嵌套）。
- **执行仍在 app**：`plan`（一次 LLM 往返）与 `tools`（审批/流式/痕迹）由 `app.py` 步循环**托管执行**，
  引擎侧没给它们注册 handler。所以图不是"通用的 agent 引擎"，而是**控制流层**。
- 图写坏 / 名字拼错 / 引擎报错 → **逐级降级**：全流程 → 只驱动收尾路由 → 纯硬编码，并打 `⚠️`。

## 2. 三档开关（可切换，默认见括号）

| 键 | 默认 | 含义 |
|---|---|---|
| `flow_enabled` | `1` | 关 = **纯硬编码**（完全不读图） |
| `flow_full` | `0` | 开 = **图驱动全流程**（迭代决策也由图定）；关 = 只驱动"无调用收尾路由" |
| `flow_name` | 空 | 用哪张图；空 = 用**智能体名**（当前 `default_intelligent_agent`） |

**档位也可以是「智能体属性」**（2026-10-04）：`agents/<名>.json` 里的

```json
{"name": "default_intelligent_agent", "flow": {"enabled": true, "full": true, "name": "default_intelligent_agent"}}
```

- **解析顺序**：智能体 `flow.*` → 全局 `flow_*` → 图名再空就用智能体名。实现见
  `app.py:_agent_flow_cfg()`；`GET /api/flow/status?agent_name=<名>` 会回 `agent_flow` 原样字段。
- 于是「一个智能体 = 一套控制流」：`default` 不写 `flow` → 跟全局；脑图智能体写死自己的图与档位
  （实测：全局 `flow_full=0` 时它仍 `mode=full, source_kind=user`）。
- 改法：设置页「🧠 智能体与技能接线」（暂未暴露 `flow` 编辑项 → 用 API/手写 json）
  或 `POST :1250/api/agents`（body 带 `flow` 字段，`agents.py:_norm_flow` 只认
  `enabled/full/name` 三个键，类型不对就丢）。
- 全局三档改法：agent 设置页 / `POST :1250/api/settings` `{"settings":{...}}` / 工作区
  `<数据根>/l_agent_chat/.l_agent_ws/settings.json`（watcher 2s 内热生效，无需重启）。

## 3. 图在哪、怎么看

### 3.0 图现在管什么、还有什么不在图里（2026-10-05 重画后）

**一张图**：`default` 与 `default_intelligent_agent` 两个智能体共用 `default_intelligent_agent`
（`_agent_flow_cfg` 的缺省图名改了；包内置 `default.json` / `default_intelligent_agent.json` 同内容兜底）。
以前两张一模一样的图分别维护，编辑器改了用户那份对 `default` 智能体不生效。

| 管什么 | 在图上的位置 | 以前在哪 |
|---|---|---|
| 去工具 / 继续规划 / 收尾 | `branch_calls` / `branch_steps` | 图（不变） |
| **熔断、工具要求停、步数用尽** | `branch_steps` 的 `fail_limit_hit` / `stopped` / `steps_exhausted` → **`end_abort`**（`result=abort`） | 步循环里直接 `break`，轨迹里断头（约 13% 轮次 `end=''`） |
| goal 超时 | 步循环检测后**记成 `end_abort`** 写进轨迹 | 不记 |
| **只看不改提醒** | `gate_idle`（`guard=idle`，`params.after/every/prompt`），挂在迭代路径 | 步循环尾部硬编码 |
| **按事实选门** | `branch_work`：`wrote_not_verified → gate_verify`、`not_wrote_any → gate_stall`、其余直达 `gate_fact` | 每轮四道门挨个跑（纯问答 4 → **2** 道，写+验证 4 → **1** 道） |
| 收尾确认开关 | `branch_confirm`（谓词 `confirm_enabled`）+ `gate_confirm.params.enabled` | 只在设置页 `confirm_before_finish` |
| **每道门拦几次、什么阈值、说什么** | 门节点 `params`：`enabled` / `max` / `reply_chars`（stall）/ `prompt` | 代码里写死 |
| **熔断阈值、重复读上限、空手收工字数、空转节奏** | 图级 `params`：`max_consecutive_failures` / `read_repeat_limit` / `stall_reply_chars` / `nudge_after_steps` / `nudge_every_steps` | 只在设置页 |

`params` 缺省 = 原来的代码默认值，所以没写 `params` 的旧图行为不变；门 `params.enabled=false` 时
引擎**直接放行**（不调护栏）。编辑器属性面板：门节点有「护栏参数」表单，全局面板有「图级参数」表单。
`flow_spec.save_flow` 与编辑器 `toStorage` 都会**保留** `params` 与 `_ui`（以前 agent 侧一保存就把它们抹掉）。

**仍不在图里**（有意保留在代码）：`plan` / `tools` 的执行本体（LLM 往返、工具审批 / 流式 / 痕迹）、
门的**判据结构**（比如 stall 怎么认出"开场白"、fact 怎么认出"代码问题"）、重复读的计数实现、
第 0 步强制先复述。图决定**路线、开关、阈值和提示词**，代码只负责"怎么判、怎么执行"。

新增谓词：`not_fail_limit_hit` / `stopped` / `goal_timeout` / `aborting`（任一中止）/
`wrote_not_verified` / `idle_no_write` / `confirm_enabled`；新增护栏名 `idle`。

- **文件**：`<LUGWIT_DATA_ROOT>/l_agent_chat/flows/<名字>.json`
  （用户目录优先 → 包内置 `l_agent_chat/.../flows/default.json` 兜底）。
- **编辑器**：`http://127.0.0.1:8080/mindmap-mmd/flow/<名字>`（直连 `:8110/flow/<名字>`）。
  改完点保存即生效；`sub` 节点在「添加 → sub」里放，属性面板选子图。
- **权威状态**：`GET http://127.0.0.1:1250/api/flow/status`
  → `mode=full|routing|hardcoded|off`、`loaded`、`source` + `source_kind=user|bundled`、
  `resolve_name`、`no_calls_start`、`flow_full_active`、`reason`。
  编辑器右侧「智能体驱动就绪度」同时显示**本地近似**与这条**权威值**（含"当前跑的其实不是这张图"提示）。
  该端点还带**图长相**：`nodes_count` / `gates[{node,guard,label}]` / `subs[]` / `description`
  —— 对话里的顶栏徽标与 `/flow` 面板用它（2026-10-05 增）。

### 3.1 在对话里怎么看（四层，2026-10-05 补齐）

补之前："图驱动"在界面上只有开头一行 `🧭 图驱动全流程：…` status，路线 / 门触发 / 命中
**只落 `_traces/*.jsonl`**（要开编辑器才看得到），两处 `run_flow(...)` 还是 `emit_nodes=False`
（节点事件压根没发出去）—— 所以脑图智能体看着和普通智能体没区别。现在四层：

| 层 | 位置 | 说明 |
|---|---|---|
| **路线条** | 每条回答的「过程」流水 → `🧭 控制流` 一行 | 本轮实际走过的节点（`plan → branch_calls → gate_stall⁴ → …`），被护栏拦的门**标红带次数**；`脑图 ↗` 一键开编辑器那张图 |
| **常驻徽标** | 顶栏第二行 | `🧭 <图名> · <档位> · N 门`；纯硬编码时 `🧭 硬编码`（标黄）。切智能体即变（换智能体 = 换一套控制流） |
| **`/flow` 面板** | 点徽标 或 输入框 `/flow` | 档位 + 说明、命中文件（用户目录 / 包内置）、节点数、门清单、开编辑器、`/youhua_agent` 提示 |
| **策略建议** | 收尾前（有才出） | `🔧 策略建议（改图后下一轮生效）：…`，见 §7.1 |

实现要点（改这块**先读**，两个坑）：

1. **引擎吐 dict，生成器吐字符串**：`flow_engine.run_flow` 的节点事件是 `ctx.emit(dict)`，
   而 `_chat_events` 这个 async generator 其它分支 yield 的都是 `_sse(...)` 字符串 ——
   转发处必须 `yield _sse({**_ev, "flow": <图名>})` 包装，**别**写回 `yield _ev`（裸 dict 会混进
   SSE 体，前端只看到解析失败）。
2. **护栏不能 yield**（同步返回 bool）：要在 `_wrap_guard` 里 `ctx.emit({"type":"flow_gate",…})`，
   由引擎在下一个节点后 `_drain()` 带出来 —— 这是引擎既有的 handler/guard 事件通道。
3. **刷新后要还在**：实时事件只活在这一轮；轮末再发一条带 `flow={name,path,gates}` 的**终版**
   status，它落进 steps（`_mark` 原样存），前端按同 key 原地更新那一行并在历史重建时认领
   （`s.flow` → `kind="flow"`；后端 steps 里没有 `kind` 字段，全靠这个认领）。

## 4. 运行轨迹（A1：热力 + 回放）
- agent 每轮把轨迹追加到 `<flows 目录>/_traces/<图名>.jsonl`（只留最近 200 轮）：
  `{ts, mode, steps, end, dur, seq, segs, guards}`；`segs` 是每次 `run_flow` 的分段（算边热力**必须**分段，
  否则段间拼接会造出不存在的边）。
- 编辑器工具条 `📈 轨迹`：图上节点/边热力徽标 + 逐轮回放（轮次/步进/元信息）+ 刷新/清空。
  接口：`GET|DELETE /api/flow-traces/{name}`（聚合时按 `_flow_edge_set` 只保留图上真实存在的边）。

## 5. 策略包（C4：图 + 观感 + 档位，一键切换）

- 工具条 `📦 导出策略` → `<图名>.preset.json`：
  `{kind:"lugwit-flow-preset", version, exported_at, flow, edgePrefs, agent:{flow_enabled, flow_full, flow_name}}`。
- 导入：`📥 导入策略` 或**把文件拖到画布上** → 写回流程图 + 应用观感设置 +
  （agent 可达时）应用档位；agent 不可达只跳过档位并如实提示。
- agent 接口：同源 `/agent_chat/api/*` 优先，退本机 `:1250`。

## 6. 编写图时的硬约束（编辑器 + 服务端会拦）

- **`branch_calls` 必须有 `has_calls` 分支、`branch_steps` 必须有 `steps_exhausted` 分支**，否则只能驱动收尾路由。
- **branch 必须有一条无条件兜底**（末条 `when: always`）；谓词必须是引擎表里的名字（编辑器下拉可查）。
- **gate 的 `guard` 要用已注册名**（`stall/verify/fact/confirm`），写别的 → 运行时回退硬编码。
- 别把 action/branch 指向**装饰节点**（comment/tag/summary）—— 引擎会报"没有下一步"。
- `sub` 不能自指，同调用链不允许重复子图名，嵌套深度 ≤ 8（防环）。
- 保存时的权威校验：`PUT /api/flows/{name}` 会先跑 `l_agent_chat.flow_spec.parse_flow`
  （同 env 直接 import；不同 env 调 `POST :1250/api/flow/validate`，该接口额外查**谓词名**）；
  都不可用 → 跳过（哑存储兜底）。编辑器侧还有一套等价校验挡在保存前。

## 7. 策略诊断与自我复盘（D7）

### 7.1 每轮自动打一行（规则式）
- `l_agent_chat.flow_spec.diagnose(spec, run, flow_full=...)`：规则式给"能落到图上动作"的建议
  （缺结构 / 护栏一轮拦 ≥2 次 → 加 `nudged` 分支 / 步数用尽 → `steps_remain`·`budget_exhausted` /
  goal 模式没用到 `budget_low` / branch_calls 缺兜底）。
- app 每轮结束后按**真实运行数据**打一条 `🔧 策略建议（改图后下一轮生效）：…`（前 2 条），
  并写进过程流水。**只提示，不自动改图**。

### 7.2 按需自我复盘工具 `optimize_agent`（2026-10-04）
**不是每轮自动跑** —— 它是一个普通工具（`l_agent_chat/flow_evolve.py`），三条触发路径：
输入框 `/youhua_agent [重点]`（后端把斜杠展开成明确指令）· 模型自己判断调用 ·
或脚本直接调 `optimize_agent(...)`。

| | |
|---|---|
| 取证三块 | ① `tools`：本轮工具**慢（≥20s）/ 失败 / 反复调用** + 耗时 top ② `flow`：图结构 + 本轮路径 + 护栏触发 + 近 N 轮热点/均步数 + `diagnose` 规则建议 ③ `docs`：本轮知识类工具调用 + **用本轮用户问题反向检索知识库**（有货=本可先查；0 命中=知识缺口） |
| 参数 | `focus=tools|flow|docs|all`、`scope=last|recent5`、`action=report|verify|apply`、`edits`(JSON)、`why`、`force` |
| 只读 | `action="report"`（默认）：只出材料，**结论与优化建议由当前这轮的模型自己写**（不额外烧 LLM） |
| 沙箱验证 | `action="verify"`：候选图 vs 现状图的**路由回放 A/B**（见 §7.3），只回结论、**不写盘** |
| 落地 | `action="apply"` + `edits`：`{"flow": 整图}` / `{"note": {kb, rel, text}}` / `{"memory": {file, section, key, text}}`；图改动先过 `parse_flow` + 结构检查（会让全流程驱动降级的**拒收**）→ **沙箱路由回放**（报回归默认拒收）→ 备份 `flows/_versions/<图名>/<ts>.json` → 原子写 → 记 `_traces/_applied.jsonl`（含 `force`/`verify`） |
| 数据来源 | `app.py` 每轮结束 `flow_evolve.set_last_run({...})`（同进程，最准）；图/轨迹走 `flow_spec`；知识库走 `notepad_knowledge`（:8765）；记忆走 `memory.upsert` |
| 常驻声明 | 在 `tool_router.CORE_NAMES` 里（否则 `/youhua_agent` 会先绕一次 `find_tools`） |

**红线**：只改**数据**（图 / 笔记 / 记忆），不改引擎与代码；`apply` 走校验 + **回放** + 备份 + 留痕，可回滚。

### 7.3 沙箱自验证（三层，2026-10-04）
"让 agent 自我进化"必须先能**在不产生副作用的前提下验证**，否则改错了没人知道。三层由粗到细：

| 层 | 机制 | 位置 | 判据 |
|---|---|---|---|
| ① 路由回放 | 候选图 vs 现状图跑同一批场景（**假 handler / 假 guard**，不联网、不执行任何工具）：6 条合成 fixture（空手收尾 / 有调用 / goal 未收束 / 步数用尽 / 护栏触发一次 / goal 预算见底） | `flow_evolve.verify_flow` | 新图**报错** / **不收尾** / **护栏触发从 N 次掉到 0**（拆护栏）/ **访问节点明显变多**（绕远）→ 只要一条就 `ok=False` |
| ② 演练模式 | `with flow_evolve.dry_run():` → `l_agent_tool.agent_tools.set_dry_run(True)`，**写类工具一律拒**（`DRY_RUN_BLOCKED`：write/edit/notepad_modify/memory_write/run_command/todo_write/ask_user/multi_ai…），读类照常 | 拦截点在 `AgentTool.__call__` —— `tools.call()` 与 `tools.write_file(...)` 属性式调用**都必经**这里，一处收紧全覆盖；MCP 工具（浏览器点击 / POPO 发消息）另在 `mcp.call_tool` 单独拦一道。开关是**线程本地**的（多会话共进程不互相误伤），可嵌套 | 演练期内写类返回 `{"blocked": True}`，磁盘/网络零副作用（实测文件没生成）；`action="verify"` 全程套在这层里 |
| ③ 历史轮次回放 | 用 `_traces/<图名>.jsonl` 里**真实跑过**的 `guards`/`steps`/`seq` 还原初始状态再回放（补合成 fixture 盖不住的组合："某道门连响两次 + 步数刚好卡 3"） | `flow_evolve._trace_scenarios`（`verify_flow(history=True)` 默认带最近 5 轮） | 同 ① |
| ④ 对话录像回放 | 用 `recorder` 的 **cassette**（真实模型调用的请求/响应）还原"每一步真调了什么工具"：按首条 user 消息分组 → `response.body` 抠工具名（真·OpenAI 形状），实机（deepseek-v4 走 l_model_hub，不吐 `tool_calls`）则从**下一轮请求**的 `role=tool` / `Tool execution results (JSON)` 回灌块里取、并**左移一格**对齐到"哪一步调的" | `flow_evolve._cassette_conversations`（`verify_flow(cassettes=True)` 默认带） | 同 ① |

- `apply` 的拒收是可**人工放行**的：确属有意为之带 `force=true`，留痕里记 `force` 与回放结论。
- `l_agent_tool` **不反向依赖** `l_agent_chat`：开关状态住在 `agent_tools`，`flow_evolve` 只是驱动它。
- 场景来源会在报告里明示（`场景构成：合成 6 · 历史轨迹 5 · 对话录像 4`）；没有 cassette 时提示
  "想要更真：开 `recorder_mode=record` 录一轮真实对话"。
- **没做**：拿 cassette 把 **LLM 也回放一遍**（即跑完整一轮 turn 的 A/B）—— 现在回放的是"真实输入
  状态 + 假 handler"，LLM 结果不重算；要真做到那步得让 `recorder_mode=replay` 跟每个"候选图"各跑一遍
  真实 turn，成本高且要处理回合间的状态残留。当前 ④ 已经把"这一步真调了哪些工具"喂进来了，
  对**路由类**改动（分支/护栏/子图）已经够用。

## 8. 引擎能力一览（写图时可用的积木）

**能表达的只有四样：路线、出口、开关/阈值/提示词、迭代节奏**；判据与执行都在代码里（见 §3.0）。

- 节点：`start` · `plan` · `tools` · `branch{cases:[{when,to}]}` · `gate{guard,on_trigger,on_pass}` ·
  `sub{flow,next}` · `end{result}` · 自定义动作（**需宿主注入同名 handler**，见下）· 装饰 `comment/tag/summary`（执行时忽略）。
- 节点/图 `params`：门 `{enabled,max,reply_chars,prompt,…}`、图级
  `{max_consecutive_failures,read_repeat_limit,stall_reply_chars,nudge_after_steps,nudge_every_steps}`（缺省 = 原代码默认）。
- 谓词（32）：`always/true/false`、`has_calls/no_calls`、`wrote_any/not_wrote_any`、
  `verified_any/not_verified_any`、`read_any/not_read_any`、`located_any`、`did_tools/not_did_tools`、
  `goal_mode/not_goal_mode`、`goal_done/goal_unfinished`、`budget_exhausted`、`fail_limit_hit`、
  `steps_exhausted/steps_remain`、`nudged/not_nudged`、`budget_low`、
  `not_fail_limit_hit`、`stopped`、`goal_timeout`、`aborting`（任一中止）、
  `wrote_not_verified`、`idle_no_write`、`confirm_enabled`。
- 状态（由 app 发布到 `ctx.state`，谓词只读、handler/guard 可读写同一份）：`step/max_steps/calls/reason/
  goal_mode/goal_result/wrote_any/verified_any/read_any/located_any/did_tools/fail_limit_hit/
  budget_exhausted/stop_loop/goal_timeout/confirm_enabled/nudges/goal_seconds/budget_left_s/idle_after`。
- 宿主当前**注入的** handler / guard（其余名字一用就 `FlowRunError` → 本轮降级硬编码）：
  handler = `plan`（= 回循环哨兵，置 `_back="plan"`）、`goal_nudge`；`tools` 是**占位标记**，
  执行在 app 步循环里（引擎不会走到它）。guard = `stall/verify/fact/confirm/idle`（各带判据结构，只在图上配阈值/次数/提示词）。
- 引擎硬保护：`MAX_VISITS=20000`（防活锁）、`sub` 嵌套 ≤ 8 且同链不重复子图名。
