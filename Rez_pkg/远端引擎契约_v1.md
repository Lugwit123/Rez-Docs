# 远端引擎契约 v1（宿主 ↔ l_mindmap_mmd 脑图）

> 面向"**把 l_node_engine 跑在别的进程里，让我们的脑图接上去**"这件事。
> 参照实现（纯标准库、可跑）：`rez-package-source/l_mindmap_mmd/999.0/tools/engine_fake_host.py`；
> 我们这侧的客户端：`src/l_mindmap_mmd/engines.py`；配置项与降级规则见本文 §4。

## 1. 为什么是"图随前端走、引擎只做 schema + 执行"

`l_node_engine` 的承诺是"**任意 python 对象在进程内传递**，只有交回给 agent 的那一份才序列化"。
所以把宿主里的对象搬到脑图进程是不可能的（也不该做）。正确的切法是：

```
浏览器 ──► l_mindmap_mmd（8110：UI + 图文件 + 轨迹/历史/会话 + 错误映射）
                 │
                 ├─ local          （本进程引擎，全功能）
                 ├─ HttpEngine ──► 宿主 A（你们的进程，契约 v1）  ← 对象只活在它自己进程里
                 └─ HttpEngine ──► 宿主 B（以后别的工具/流水线）
```

- **图文件永远在编辑器这边**（`pygraphs/<名>.json`）：跑图时把**整张 prompt** 发给宿主，宿主不用存图、
  不用协商 id 空间；换引擎**不改图**（引擎名只落在 URL `?engine=<id>` 与本机偏好里）。
- **对象不搬家**：宿主想要"让图操作我们程序里的对象"，用的是引擎自带的那条路 ——
  `l_node_engine.objects` 的**实例注册表**（`pkg.mod:Cls(tag="a")` 这种稳定键）+ 图里的
  `MakeInstance` / `GetAttr` / `CallMethod` / `GetItem` / `CallFunction`。HTTP 上只出现
  "键 / 类型 / repr"（见 `/engine/instances`）。
- **能力靠声明**：宿主在 `/engine/info.features` 里说自己支持什么；没说的一律当"不支持"，
  编辑器会把对应功能降级并在界面上说明（**不假装支持**）。

## 2. 契约（宿主必须实现）

鉴权：只绑 `127.0.0.1`，并校验一个共享 token（我们发 `X-Engine-Token: <token>`；
也认 `Authorization: Bearer <token>`）。token 配不上请回 **401**。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/engine/info` | — | `{contract:"1", name, version, python, node_count, features:[...]}` |
| GET | `/engine/nodes` | — | **object_info**：`{类名: {input:{required,optional}, output:[...], ...}}`，与本地 `l_node_engine.get_all_node_info()` 同形状 |
| POST | `/engine/run` | `{prompt, run_id, contract, interface?}` | `{ok, outputs, node_errors, order, steps?, error?}` |
| GET | `/engine/instances` | — | `[{key, type, repr}]`（宿主实例注册表的清单；**不搬对象**） |
| GET | `/engine/classes?q=&pkg=&limit=` | — | 可选（`features` 里有 `classes` 才调）：**搜类** → `{classes: [{path, name}], count}`。⚠ 只搜**已经导入**的模块（不 import 新东西）—— 直接复用引擎的 `classes.FindClasses` 最省事（口径与图里的节点完全一致） |
| GET | `/engine/ports?target=&method=&kind=` | — | 可选（`features` 里有 `ports` 才调）：与本地 `/api/pygraphs/ports` 同形状 |
| POST | `/engine/validate` | `{prompt}` | 可选（`features` 里有 `validate` 才调）：`{errors:[{node,message,code?}], warnings:[...]}` |

### 2.1 `run` 的细节（照抄这几条就不会漂）

- `prompt` 就是引擎的 prompt（`{节点id: {class_type, inputs}}`，连线是 `[源id, 下标]`）——
  **我们发之前已经把子图 / 老图输入改名都归一好了**，宿主直接 `execute_graph(prompt)` 即可。
- **`interface`（可选，2026-10-18 起我们总会带）**：这一轮**图入参的值**（`{参数名: 值}`）→ 宿主转手给
  `execute_graph(prompt, emit, interface=interface)`，因为 `GetParam` / 参数卡的 `param` 行读的是
  `graph.active_interface()`。老宿主忽略这个键也没问题；但**收下它**才能跑带 `GetParam` 的图
  （不收就是 `GetParamError: 这张图没有声明入参 …`，混引擎按段跑时还会表现成"上游节点没有产出"）。
- `outputs`：按 `{节点id: 值}` 回；`Output` 节点那套 `{"result":…, "ui":…}` 由宿主先剥成 `result`
  （和我们在本地做的一样：`val.get("result") if isinstance(val, dict) and "result" in val else val`）。
- 值会给 JSON 序列化：**能 JSON 的就 JSON，不能的走 `repr`**（`json.dumps(..., default=repr)`）。
  别指望往返成真对象 —— 要"真对象"就让图在宿主里继续用（这是 B 拓扑的意义）。
- `node_errors`：`{节点id: {"errors": [{"message":…, "type":…, "details":…}]}}`（与引擎一致）。
- `order`：`["1","2",...]` 执行顺序（字符串化）。
- `steps`（可选但**强烈建议**）：每个节点一条 `{node, duration_ms, output?, cached?, skip?, bypass?, mute?, if_taken?}`。
  编辑器把它摊成前端既有的 `executed` 事件 → 节点上的耗时/复用/跳过徽标、运行日志、轨迹回放全部照常工作。
  ⚠ **`output` 就是你那份"节点内联预览"**（本地跑图时引擎里 = 节点返回的 `ui` dict，如 `{"value": ["…"]}`）：
  漏了它，编辑器**节点卡片上就没有值**（症状："跑完了，输出节点什么都看不到"，而本地跑图是有的）。
- 结构错（`GraphPlanError` / 未知节点 / 你的超时）→ `{"ok": false, "error": "人话原因"}`；
  编辑器会把它变成日志里那条 `✗ …`，并**照样留痕**（历史 + 轨迹）。

### 2.2 契约版本

`/engine/info.contract` 与编辑器认的版本（当前 `"1"`）不一致时，编辑器**拒绝连接**并给明确文案
（`409`）—— 宁可连不上，也不要"半死"：两边对同一张图的理解不同，比直接报错危险。

### 2.3 混引擎（一张图里多台引擎）宿主**不用改**

编辑器把图按"节点标注的引擎"切片，**每一段都是一次普通的整图 run**（段内保留原有连线）——
所以宿主什么都不用加：它照旧只收到"一张图 + 完整 prompt"。
**跨引擎的边**由编辑器在段边界做值交接（取上一段某节点的输出 → **JSON 化** → 填成下一段目标输入的字面量）；
JSON 不了的会退成 `repr` 字符串。限制：段间成环 / 跨引擎的循环区**不支持**（编辑器直接报错）。
细节见 `Rez-Docs/Rez_pkg/l_mindmap_mmd.md`「混引擎」一节。

## 3. 宿主骨架（bottle 版，可直接抄）

> **复制版就在仓里**：`rez-package-source/l_mindmap_mmd/999.0/tools/engine_bottle_host.py`
> —— 拿来改 `_register_local_nodes()` 即可（**已实测**：bottle 0.13.4 + 我们的 `engines.HttpEngine`
> 打它，`/engine/info`、`/engine/nodes` 与本地同表、`/engine/instances`、`/engine/run` 出结果、
> `steps` 有货、错 token → 401 全通）。下面这段是它的核心，注释把"为什么"写在一起。

> bottle 是单文件、零依赖，但**默认 `wsgiref` 是单线程** —— 跑图会卡住所有请求（连探活都超时）。
> 所以：① 用线程化的 WSGI server；② **不要**用 SSE/长连接（WSGI 下容易僵），跑图**同步返回**，
> 编辑器那边自己会把结果摊成它要的事件流。

```python
# host_bottle.py  ——  契约 v1 的 bottle 实现（20 行核心 + token 校验 + 线程化）
import json, os, sys, threading
from bottle import Bottle, request, response, run, WSGIRefServer
from l_node_engine import discover_module, execute_graph, get_all_node_info, list_instances

TOKEN = os.environ.get("HOST_TOKEN", "")
CONTRACT = "1"
app = Bottle()

def _register_local_nodes():
    """"宿主自己的节点"：import 你们的模块 → 注册进引擎（这里按需改）。"""
    for mod in [m.strip() for m in os.environ.get("HOST_NODE_MODULES", "").split(",") if m.strip()]:
        __import__(mod)
        discover_module(sys.modules[mod])

@app.hook("before_request")
def _auth():
    if TOKEN and request.headers.get("X-Engine-Token") != TOKEN:
        response.status = 401
        return json.dumps({"ok": False, "error": "token 不对"})

@app.get("/engine/info")
def info():
    response.content_type = "application/json"
    return json.dumps({"contract": CONTRACT, "name": "anim_upload_muse_tool", "version": "999.0",
                       "python": sys.version.split()[0], "node_count": len(get_all_node_info()),
                       "features": ["run", "instances", "nodes", "steps"]})

@app.get("/engine/nodes")
def nodes():
    response.content_type = "application/json"
    return json.dumps(get_all_node_info(), default=repr)

@app.get("/engine/instances")
def instances():
    response.content_type = "application/json"
    return json.dumps([{"key": k, "type": t, "repr": f"{k} <{t}>"} for k, t in list_instances().items()])

@app.post("/engine/run")
def run_graph():
    response.content_type = "application/json"
    payload = request.json or {}
    prompt = payload.get("prompt") or {}
    steps = []
    def emit(event, data):                      # 引擎的回调：把 executed 收成 steps 回给编辑器
        if event == "executed":
            steps.append({k: v for k, v in ({"node": data.get("node"), "duration_ms": data.get("duration_ms"),
                                             "cached": data.get("cached"), "skip": data.get("skip"),
                                             "bypass": data.get("bypass"), "mute": data.get("mute"),
                                             "if_taken": data.get("if_taken")}).items() if v is not None})
    try:
        outputs, node_errors, order = execute_graph(prompt, emit)
    except Exception as e:                      # 结构错：人话回给编辑器
        return json.dumps({"ok": False, "error": str(e), "steps": steps})
    return json.dumps({"ok": not node_errors,
                       "outputs": {nid: (v.get("result") if isinstance(v, dict) and "result" in v else v)
                                   for nid, v in outputs.items()},
                       "node_errors": node_errors, "order": order, "steps": steps,
                       "run_id": str(payload.get("run_id") or "")}, default=repr)

class ThreadedWSGI(WSGIRefServer):
    """bottle 自带的 wsgiref 是单线程 → 套一层线程化（跑图时探活还能回）。"""
    def run(self, app):
        from wsgiref.simple_server import make_server, WSGIServer
        from socketserver import ThreadingMixIn
        class T(ThreadingMixIn, WSGIServer):
            daemon_threads = True
        httpd = make_server(self.host, self.port, app, server_class=T)
        httpd.serve_forever()

if __name__ == "__main__":
    _register_local_nodes()
    run(app, host="127.0.0.1", port=int(os.environ.get("HOST_PORT", "8731")), server=ThreadedWSGI)
```

**注意事项（都在别处踩过）**：

1. **跑图的线程**：Qt 应用里跑图请丢到工作线程（别在主线程 `execute_graph`，界面会卡死）；
   节点里碰 Qt 对象要有数（跨线程碰 GUI 对象会炸）。
2. **进度**：v1 没有流式进度（同步一次返回）。要长任务的进度条，就在宿主侧记 `run_id → 进度`，
   自己加 `GET /engine/runs/<id>` 让编辑器轮即可。
3. **图的存储**：宿主**不需要**存图。真想让宿主也有一份，那是另一套（双 owner），v1 不做。

### 3.1 宿主自己的节点怎么进来（**别手写 scanner**）

引擎自带"**普通函数 → 节点**"的批量注册（`l_node_engine.from_functions`），宿主启动时一次就够：

```python
from l_node_engine.from_functions import register_package_functions

report = register_package_functions("anim_upload_muse_tool", category="muse")
# report = {"modules": {"anim_upload_muse_tool.xxx": ["func_a", "func_b"], …},
#           "skipped": ["… 不在导入白名单里", "名字已被占用 → 注册成 …"],
#           "errors":  [(模块, 异常), …]}
```

它能替你处理掉这几件"手写 scanner 一定会踩"的事：

| 行为 | 说明 |
|---|---|
| 只扫**本模块定义**的函数 | `__module__` 不同的一律跳过 —— 不然会把 `os.path.join`、`lprint` 这些被 import 进来的也包成节点 |
| 端口类型跟着**注解** | `str/int/float/bool/list/dict/Path/…` 以及 `list[int]` 这类自由表达式（没注解没默认值 → `*` + `forceInput` = 必须连线；有默认值 → optional） |
| 跳过噪音 | `_` 开头、零参函数、`print`/`lprint`/`main` 这类（`skip=` 可加） |
| **重名不覆盖** | 两个模块都有 `upload()` 时，第二个退成 `<模块名>.upload`（再撞加 `#2`）；重扫**幂等** |
| 导入过白名单 | 自动 import 一堆子模块这件事必须过 `L_NODE_ENGINE_ALLOW_PKGS` / `allow.json` |
| 异步函数 | `async def` 也挂得上，执行时用 `await_if_needed` 跑掉协程 |
| 一个子模块崩了不算完 | 默认记进 `report["errors"]` 继续扫（`strict=True` 才抛） |

只看不注册（打印清单/做白名单）用 `describe_module_functions(module)`；单模块用
`register_module_functions(module)`。自证：`wuwor l_node_engine -- python <包>/999.0/tools/from_functions_check.py`。

## 4. 宿主侧要准备什么（依赖 / 解释器）

**只要 `l_node_engine` 一个包**（纯标准库：不拖 aiohttp / fastapi / numpy / Qt 任何东西）。
编辑器的依赖（fastapi/uvicorn/jinja2/l_tex_nodes 的 numpy+pillow…）**全在我们这边**，宿主不背。

- **python 范围**：`l_node_engine` 现在声明 `python-3.11+<3.13`（**刻意放宽**：内核要能被
  "宿主进程"当普通库 require，比如一个跑在 python-3.11 的 Qt 工具 —— 它的 PySide6 变体就是 3.11）。
  源码里没有 3.12 专有语法（PEP 695 / `Path.walk` / `itertools.batched` / `sys.monitoring` 全无），
  3.11 起可用；`bottle` 本身是单文件纯 py，不引入新依赖。
- 两种接法：
  1. **rez 里 require**（推荐，有版本治理）：`requires = [..., 'l_node_engine']`，
     然后 `rez env <你的shell> l_node_engine -- python -c "import l_node_engine; print('ok')"`。
     货架得能看到我们的包（`REZ_PACKAGES_PATH` 加一条，或把包拷进你们的货架 —— 你们已有先例）。
  2. **`sys.path.append('<l_node_engine>/999.0/src')`**（临时探路）：内核零三方依赖，这样也能跑；
     代价是没有版本治理（改包不会跟着走），只建议当一次性的验证手段。
- 自证钩子（宿主里跑一遍就知道接得对不对）：
  ```python
  from l_node_engine import execute_graph, get_all_node_info, list_instances
  print(len(get_all_node_info()))          # 节点表（编辑器会拿它渲染）
  print(execute_graph({"1": {"class_type": "Input", "inputs": {"name": "n", "type": "int", "value": 3}},
                       "2": {"class_type": "Output", "inputs": {"name": "out", "value": ["1", 0]}}})[0])
  ```

## 5. 我们这侧怎么配

配置在**数据目录的 `engines.json`**（或 env `L_MINDMAP_ENGINES` 给 JSON 数组覆盖）：

```json
{ "engines": [
  { "id": "anim", "label": "anim_upload_muse_tool", "url": "http://127.0.0.1:8731",
    "token": "…", "enabled": true }
] }
```

- 接口：`GET /api/engines[?probe=1]`（清单 / 探活）、`PUT /api/engines`（整表覆盖）、
  `GET /api/engines/<id>/instances`。
- 请求侧：`/api/pygraphs/object_info`、`/ports`、`/validate`、`POST /api/pygraphs/<名>/run` 都吃
  `?engine=<id>`；**不带 = 本地引擎**（老行为一个字没变）。
- 界面：工具栏的引擎下拉（`?engine=` 写进地址，可分享/可脚本化）；
  离线引擎标 ⚠、切过去会明确报错并提示切回本地。
- 降级规则（宿主没声明对应 feature 时）：

| feature | 没有时 |
|---|---|
| `validate` | 权威校验跳过（回 `skipped:true` + 一条提醒），编辑器只做本地结构检查 |
| `renders` | 没有节点缩略图 / 2D 取景器（远端不缓存渲染结果） |
| `ask` | 不支持人在环 `Ask` 节点（宿主没挂钩子，跑起来会软失败并说明） |
| `incremental` | 每轮全量重算（无增量烹饪） |
| `ports` | `CallMethod` / `CallFunction` 的动态端口问不到 |

### 6.1 muse 真宿主：本机怎么起（`tools/start_muse_engine.bat`）

那个"真宿主"就是 `anim_upload_muse_tool` 那套（节点来源 `category:"muse"`），**不是 wuwo 服务卡片**
（用户口径：这个引擎不由 wuwo 起；`wuwo svc list` 里看不到它，启停就是那个 bat 窗口）。

**为什么不能 `wuwor`**：wuwo 会**无条件**注入自己的 core 包（`l_app_ready` / `platform` … 钉死
`python-3.12`），而 muse 那堆依赖（`pipe` / `muse_pipe` / `narcolab` / `p4v` / `PySide6` …）只认 ≤3.11
⇒ `wuwor` 拼这个环境必冲突。两边都接受的口径是 **python-3.11**（`l_node_engine` 声明 `3.11+<3.13`）。
所以走**他们自己的启动器** `D:\TD_Depot\Software\PATH\ru.bat`
（= `WuzuCMD.exe -a -s powershell -c %*`）。⚠ WuzuCMD 两条规矩：命令**不带** `rez env wuzu` 前缀时
只能写 `-c`（写 `--` 被拒，回话是"改为 -c"）；且 `-c` 只吃**一个 token** ⇒ 那条命令必须落成一个脚本文件。

| 文件 | 作用 |
|---|---|
| `l_mindmap_mmd/999.0/tools/start_muse_engine.bat` | 外层：清代理 env → 设货架/白名单/端口/token → `call ru.bat "rez env python-3.11 l_node_engine anim_upload_muse_tool -c …\muse_engine_host.bat"` |
| `…/tools/muse_engine_host.bat` | 内层（`-c` 的唯一 token）：`python engine_fake_host.py --port %L_MUSE_HOST_PORT% --token %L_MUSE_HOST_TOKEN%` |

它设的 env（缺一条就挂不上节点）：

  → `outputs {"2":[true], "3":[73310]}`、`order` 正确、`steps` 有耗时 ⇒ **执行面通**，不是只探活

**三个坑**：

1. **包一 import 就 `sys.exit()`**：`anim_upload_muse_tool` 的 `__init__` 带自检（实测报
   `ERR muse_tool.py: L1 invalid non-printable character U+FEFF`）→ `SystemExit` 不是 `Exception`，
   旧代码兜不住 ⇒ **宿主静默退出**（端口没起、日志停在那行、看不到任何异常）。
   修在 `from_functions.register_package_functions`（包导入与逐子模块导入两处）与
   `engine_fake_host._register_host_packages`：一律 `except BaseException`（`KeyboardInterrupt` 照旧 re-raise）。
2. **`-c` 只收一个 token**：把 `python … --port … --token …` 全塞进 `-c` 会被截断 → 内层 bat。
3. **代理**：外层 bat 先清 `HTTP(S)_PROXY` / `NO_PROXY=*`（同他们那些 `run_*.bat`）——带代理时
   127.0.0.1 的往返在某些 shell 里会被绕出去。


## 附：**可选**扩展 —— 增量烹饪缓存（2026-10-24）

远端宿主本身就跑 `l_node_engine`，所以**缓存实现已经在引擎包里**（`l_node_engine/cook_cache.py`：
内存层按 `L_MINDMAP_COOK_MEM_MB`、磁盘层 pickle + 大数组去重 + 真 LRU + TTL 清扫）。
宿主那边只要三件事（`tools/engine_fake_host.py` 就是范例）：

```python
from l_node_engine import cook_cache

cache = cook_cache.cook_cache_for("<图名>", "<落盘目录>")   # 每张图一份，进程内复用
cache.begin_run()                                          # 每轮开头清"本轮命中明细"
execute_graph(prompt, emit, interface=interface, cache=cache)
```

再把统计回出去（编辑器面板「远端」那一行读它）：

```text
GET /engine/cache  →  200 {"ok": true, "cache": {"mem_bytes":…, "disk_bytes":…, "hit_rate":…,
                            "last_hits": [...], "top": [...]}}
```

- **不支持**这个接口的老宿主：宿主侧记成"离线 / 没这接口"（`_REMOTE_CACHE_STATS`），不影响跑图；
- 两端都会缓存（编辑器缓存**整段**结果、远端缓存**每个节点**），远端那份更细，命中时连节点都不执行；
- 想让远端不缓存：`POST /engine/run` 里带 `{"incremental": false}`。
