### 1.4 `GET xpan/multimedia?method=filemetas`（批量取元信息，含下载链）

`fs_id` · `path` · `filename` · `size` · `isdir` · `category` · `md5`（混淆） ·
`dlink` · `server_ctime` · `server_mtime` · `local_ctime` · `local_mtime` · `oper_id`

- 一次最多 100 个 fsid；`&thumb=1` 追加 `thumbs`（本机返回 `{}`）；`&extra=1` 无新增字段。
- `dlink` 需带 `access_token`（必要时加 UA）才能下载。
- **注意**：`dlink` 的 URL 路径里就是那个混淆值，例如
  `https://d.pcs.baidu.com/file/d208646ebo3157c8d1db9b5f1558ed9a?fid=...`
  → 说明百度内部就拿这个值当内容标识（所以它同内容稳定）。

### 1.5 `GET xpan/file?method=search`（按名搜索）

基础字段 + `score` · `relevance_level` · `ptype` · `fold` · `recent_tag` ·
`docpreview` · `thumbs` · `delete_type` · `from_type` · `extent_tinyint1` · `extent_int8`

### 1.6 `GET xpan/file?method=listall`（递归全量）

**不可用**：HTTP 403 `error_code=31064 file is not authorized`（该接口需额外授权）。

### 1.7 `filemanager opera=copy|delete|rename`（写操作）

- `copy`：请求 **`filelist` 必须是对象数组、每项自带 `dest`（可带 `newname`）、不能带 `async`**，
  一次调用不能重复同一 src，目标目录必须先存在；成功返回 `info[i] = {errno, path, to_fs_id, to_path}`。
- `delete`：`{errno, info[], request_id}`（`errno=-9` 幂等视为不存在）。
- `rename`：`{errno, info[], request_id}`。

## 2. `md5` 字段：混淆指纹，**不能当 md5**

| 项 | 实测 |
|---|---|
| 上报值 | `d208646ebo3157c8d1db9b5f1558ed9a`（32 位，**含非 hex 字符 `o`**） |
| 真值（下载后本地算） | `319a9a27d32b21099cf32075d0f8de38` |
| 差异 | 逐位几乎全不同（非简单字符替换/XOR） |
| 同内容稳定性 | 源 + 两份云端 `copy` 副本，三次上报**完全一致**；`search` 里另一个文件也是同款形态 |
| 结论 | **确定性内容指纹**（可用于"同内容判定"、可做快速去重探测），**不可**当 md5 用于文件名/引用；也**无法本地复算** |

### 2.1 它到底是什么？（280 样本分析，`tools/baidu_md5_probe.py`）

拿 `blob/<库>/<md5[:2]>/<md5>` 里**文件名就是真 md5**的 280 个文件做对照：

| 观察 | 结果 |
|---|---|
| 长度 | 280/280 全部 32 位 |
| 字符集 | `0-9a-v`（32 个字符）——但**这不是 base32** |
| 是否逐位置替换 | 否（用 base36 偏移假设去拟合才会"冲突"），真算法见 §2.2 |
| 内容相关性 | 只取决于内容（同内容换名/换目录 → 同值），与路径/文件名无关 |
| 接口一致性 | 同一 fs_id，`file_list` 与 `filemetas` 给的值相同 |

**更正（2026-09-14）**：早期结论写的"带密钥的 160 位指纹、无法还原"是**错的**。
它是**可逆的编码混淆**，算法在 AList 里已经实现，我们已移植并实测通过。

### 2.2 真算法：EncryptMd5 / DecryptMd5（可逆）

来源：AList `drivers/baidu_netdisk/util.go` 的 `EncryptMd5` / `DecryptMd5`。
我们移植到 `src/lugwit_baidu_netdisk/baidu_netdisk_api.py`：
`encrypt_baidu_md5()` / `decrypt_baidu_md5()`。

```
标准 md5 = 32 位十六进制，切成 4 个 8 位块 b0 b1 b2 b3
上报值 = 对 (b1 + b0 + b3 + b2) 逐位做：
    n = nibble ^ (i & 15)            # i = 位序 0..31
    第 9 位特殊：字符 = chr(n + 'g')  # ← 所以第 9 位总是 g..v 的字母
    其余位：字符 = n 的十六进制
```

还原就是反过来（先逐位还原 nibble，再按 `[8:16]+[0:8]+[24:32]+[16:24]` 重排回原块序）。
**为什么早期分析没看出来**：我当时用"base36 字母表 + 固定偏移"去拟合，忽略了
① 异或的是 `i & 15` 而不是常量偏移，② 第 9 位换成 `chr(n+'g')`，③ 输出前还有一次块重排。

实测校验（`tools/baidu_md5_probe.py`，样本 = `blob/l_wchat/**` 里**文件名就是真 md5**的文件）：

| 校验 | 结果 |
|---|---|
| `DecryptMd5(上报) == 真 md5` | **279/280** |
| `EncryptMd5(真) == 上报` | **279/280** |

（唯一 1 个不匹配是早期测试残留、文件名本身不是内容 md5 的样本，与算法无关。）

已知内容对照（`tools/baidu_fp_known.py`）：`""` 的上报值
`8e23f7635tb64136eddb0719602bc477` 还原后正是 `d41d8cd98f00b204e9800998ecf8427e`（空串的 md5）✓

### 2.3 对我们的意义

| 之前 | 现在 |
|---|---|
| 必须下载文件才能得到真 md5 | **可直接从 API 返回值还原出真 md5**（零下载） |
| 存量迁移要逐文件下载算 md5 | `depot_import_tree.py --no-download`：还原 md5 → 云端 `copy` 搬到 blob 路径 → 登记，**全程零下载、零上行** |
| 上传后只能校验 size | `ensure_blob` 现在比对**还原出的真 md5**，是真正的端到端校验 |
| `remote_meta().md5_trusted` 恒为 False | 现在恒为 True（能还原），字段改为 `md5_real`（还原值）+ `md5_trusted`（能否还原） |

注意两点：
- 秒传/上传仍然由**我们自己算真 md5**（`precreate` 传分片 md5），不依赖这个还原值；
  还原值用于**读侧**（识别云端已有内容、校验、判定同内容）。
- 仍保留 `scan_file()` 作为兜底：万一某账号/某场景返回不可还原的值，代码会失败而不是静默错。

## 3. 业务使用建议

| 用途 | 用什么字段 |
|---|---|
| 内容寻址 / 版本引用 | 自己算的 md5（`scan_file`） |
| 上传后校验 | `filemetas.size`（可信）；`md5` 仅当 `md5_trusted`（实测恒假）时比对 |
| 同内容/秒传探测 | 混淆指纹（稳定）+ `size` |
| 列目录 / 枚举 | `list` 的 `fs_id/path/server_filename/size/isdir/category` |
| 下载 | `filemetas.dlink` + `access_token` |
| 容量/账号展示 | `/api/quota`、`nas?method=uinfo` |
| 云上搬运（复制/改名） | `filemanager opera=copy`（形态见 §1.7） |

## 4. 已知限制

- `listall` 403（31064）：需要额外授权，别依赖它做全量枚举 → 用 `list` 递归（本包
  `iter_remote_file_items` 就是这么做的）。
- `list&folder=1` 返回被裁剪，不能当通用列表。
- `filemetas` 单次 fsid 上限 100；`dlink` 有效期有限，取到要尽快用。
