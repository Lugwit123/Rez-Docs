## 9.8 各包登录接入现状与 SSO 一致性差距（2026-10-02 盘点）

> 目的：用户要求**每个包登录体验一致**。下表盘点了各包当前的登录/鉴权接入方式与统一状态；
> ✅ = 走统一 lugwit_auth(1027)，❌ = 未统一，⚠️ = 设计性差异（离线验签 / 匿名本机工具）。

| 包 | 登录方式 | 统一 SSO | 差距 / 建议 |
|---|---|---|---|
| `l_tray` | stdlib PKCE，`login_via_browser`，refresh 存 DPAPI | ✅ | 已统一（`Rez_pkg/l_tray.md` §3） |
| `l_qframelesswindow`（标题栏） | SDK PKCE + 密码降级，`restore_session` 续期 | ✅ | 已统一；`login_store.py` 遗留 `save_token/load_token` 明文 `auth_token.json` 读写函数**主路径已不读**（可删，2026-10-02 核实现状） |
| `l_WChat` | 浏览器 SSO：`/api/lugwit/sso/start` + callback，网络校验 `/auth/me` | ✅ | 已统一（设计 §9 P5 验收 9/9） |
| `l_agent_chat` | 本地验签，出入站双 PKCE | ✅ | 已统一。**2026-10-02 两次 nginx 修复**：(1) gate 未登录 302 到**根路径** `/api/auth/sso/start|callback`，`routes.conf` 原缺该 location → 统一入口(8080) 404，SSO 无法完成；已加 `location /api/auth/` → 1250（无斜杠保留原路径，`X-Forwarded-Prefix /agent_chat`）。(2) `/agent_chat/`、`/api/auth/`、`/note/` 补 `X-Forwarded-Host $http_host`（`$host` 不含端口 → 回调丢 :8080 白屏；样板同 `/l_wchat/`）。实测浏览器全流程通：`/agent_chat/` → SSO start → 1027 登录 → 回跳 → 侧栏显示 `👤 admin01`。notepad(`/note/`)/netdisk(`/baidu/`) 的 `/api/auth/*` 都带各自前缀走各自 location，不受影响 |
| `lugwit_baidu_netdisk` | 本地验签 + 资源级授权（`gate.require_perm`） | ⚠️ | **设计性差异**：离线验签 + 路径 owner 判定（P6），不依赖 auth 在线，保持 |
| `l_notepad_server` / `l_notepad_client` | 网络校验 `/auth/verify`；网页**已接浏览器 SSO**（PKCE start/callback，2026-10-02 落地）；本机豁免默认开 | ✅ | 网页登录已接浏览器 SSO（同 `l_WChat`：`GET /api/auth/sso/start` → 1027 authorize → 回跳换 token 写 `l_notepad_token` cookie）；本机豁免口径与全局 `LUGWIT_AUTO_AUTH_ENABLED` 对齐 |
| `l_model_hub` | 网络校验（默认 8080 nginx），凭据优先级 Bearer>插件头>cookie>env；`sk-lmh-…` 接入密钥 | ✅ | 网页登录**已统一**（无自有登录页：未登录 302 到 nginx 根 `/login`→1027，登录后写 `lugwit_token` cookie，2026-10-02 实测 302/200 全链路通过）；接入密钥是**独立体系**（给 IDE 插件用，可保留） |
| `l_homepage` | 独立门户 fqq/qwer + HMAC；**已接统一认证**（认 `lugwit_token`，2026-10-02 落地） | ✅ | 登录页新增「统一认证登录」入口（跳 nginx 根 `/login?next=/homepage`）；守卫页/顶栏用户改走 `_effective_user`（lugwit_token 优先、HMAC 应急保留）；登出同时清双 cookie。实测 302/200 全链路通过 |
| `l_log` | 浏览器 SSO（PKCE `sso/start` + `callback`，**2026-10-05 落地**）+ 闸门中间件 | ✅ | 已统一：自带 `/login` 页（只放「统一认证登录」按钮，凭据在 1027 输入）→ `/api/auth/sso/start` → 回跳换 token 写**本域** `lugwit_token` cookie；未登录**页面 302**（带反代前缀）/ **API 401**；**本机直连**（回环且无 `X-Forwarded-*`）只读免登录；上传通道（`/upload` `/upload_batch`）仍走 `L_LOG_UPLOAD_TOKEN` 机器凭据、不进闸门。实测：经反代带 cookie → `/api/logs` 200、`/api/auth/me` 200（`admin01 · 管理员`）、`/` 200，无凭据 401 / 页面 302；SSO `authorize` 对 `https://121.196.144.88` 与 `http://127.0.0.1:8080` 两个 redirect_uri 均 302 受理（未注册 URI 400） |
| `l_indextts2` / `l_ltxvideo` / `l_wanvideo` | **完全匿名**（无鉴权） | ⚠️ | 本机模型服务，匿名可接受；如对外暴露须走 nginx 加统一登录闸门 |
| `l_script_editor` | 自有 `SCRIPT_EDITOR_TOKEN` | ⚠️ | 工具 token（非用户登录），8764 供脚本/CI 用，可保持 |
| `l_scheduler` | `--auth-url` **默认指向 ChatRoom(1026)** | ❌ | **2026-10-02 已改默认到 `127.0.0.1:1027/api/v1/auth/token`**（OAuth2 表单兼容）；`LUGWIT_AUTH_URL` env 仍可覆盖 |
| ChatRoom | 密码委托 lugwit_auth 网络验证；**2026-10-02 去双轨**：统一认 `lugwit_token` cookie + RS256 统一验签 | ✅ | **已统一**：后端 JWT 改走 `app_structure.create_jwt_service()`（1027 私钥 RS256 验签 + HS256 存量兼容），首页认 `lugwit_token`/`chatroom_token` 双 cookie、API 鉴权（Bearer）可验 1027 签发 token；登录页/前端加「统一认证登录」入口（跳 nginx 根 `/login?next=/chatfront/`）。实测带 `lugwit_token` 访问首页显示 `admin01 · 管理员`、`/api/auth/me` 200（2026-10-02 端到端通过） |

**结论**：已统一的有 `l_tray` / `l_qframelesswindow` / `l_WChat` / `l_agent_chat` / `l_notepad_server` / `l_model_hub` / `l_homepage` / **`l_log`（2026-10-05）** / **ChatRoom（2026-10-02 去双轨）**；
本次文档整理顺手把 `l_scheduler` 默认登录源改到 1027（代码改动），
并落地了 `l_notepad_server` 网页浏览器 SSO（`sso/start` + `sso/callback`，端到端验证通过）、
`l_homepage` 统一认证接入（认 `lugwit_token`，HMAC 应急保留，实测通过）、
验收了 `l_model_hub`（网页登录已统一，全链路 302/200 实测通过）、
完成了 **ChatRoom 去双轨**（统一 `lugwit_token` cookie + RS256 统一验签，实测通过）、
落地了 **`l_log` 统一登录**（自带 `/login` + 浏览器 SSO，闸门 + 本机直连豁免，实测通过）。
**暂未统一（有意保留）**：`lugwit_baidu_netdisk`（离线验签 + 路径 owner 判定，设计性差异）、`l_indextts2`/`l_ltxvideo`/`l_wanvideo`（匿名本机模型服务）、`l_script_editor`（工具 token）。
