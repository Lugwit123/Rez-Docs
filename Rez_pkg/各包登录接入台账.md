## 9.8 各包登录接入现状与 SSO 一致性差距（2026-10-02 盘点）

> 目的：用户要求**每个包登录体验一致**。下表盘点了各包当前的登录/鉴权接入方式与统一状态；
> ✅ = 走统一 lugwit_auth(1027)，❌ = 未统一，⚠️ = 设计性差异（离线验签 / 匿名本机工具）。

| `l_WChat` | 浏览器 SSO：`/api/lugwit/sso/start` + callback，网络校验 `/auth/me` | ✅ | 已统一（设计 §9 P5 验收 9/9） |

## 9.9 服务间登录态：`l_agent_chat` → `l_model_hub` 的 hub token（2026-10-08 实测）

`l_agent_chat` 调模型**不再直连厂商**，而是经 `l_model_hub`(8462) 网关；该网关对
`POST /v1/chat/completions` 要求 `Authorization: Bearer <lugwit_token>`
（实测：无 token = 401；但 `GET /v1/keys?configured_only=1` **无 token 也 200**，
本机与部署机都能匿名读到全部厂商密钥 —— 这个口径要不要收，另议）。

hub token 由 `config.hub_token()` 取：**SSO 授权优先**（`sso.access_token()`，refresh 落 DPAPI），
否则用设置里的 `lugwit_user`/`lugwit_password` 自己登录（`depot_sync.lugwit_token()`）。
三处都没有 → 每次提问都报「已启用统一登录闸门，但没取到 lugwit 登录 token」（1~4s 即返回）。

- **落点（正式）**：实例数据目录 `.env`；**旧版没有 .env 支持**时用
  `<数据根>/l_agent_chat/settings.json`（`lugwit_user` / `lugwit_password`）。
  本机数据根 `~/.lugwit/main`，部署机是 `~/.Lugwit`（实例 `srv`）—— **两边目录名不同**，别照抄。
- **settings.json 会被推云**（`config.save_settings` → `depot_sync.push_settings_async`），
  但上传前经 `_redact`（`_SECRET_KEYS = ("lugwit_password", "api_key", "password", "secret")`）
  剔除凭据 → 放密码**不会上云**；源码树里的 `.env` 反而会被目录推送/提交带上，别放那儿。
- **2026-10-08 事故与修法（部署机）**：远端既无 settings.json 也无 SSO → agent 面板一直答不出来。
  写入远端 `C:\Users\Administrator\.Lugwit\l_agent_chat\settings.json`（账号复用远端已有的
  `~/.lugwit/l_log/depot_auth.json` = `admin01`）→ 重启 1250 → hub token 574 字符拿到。
  紧接着暴露**第二个坑**：远端 `l_agent_chat` 本体停在 10-02（`app.py` 292KB vs 本机 451KB），
  旧版在「检查可快速执行的指令」之后卡死（`/api/chat` 只回 `: ping` 心跳，1250 侧 8.5s 的工具
  构建与 hub 调用都正常）→ 按内容哈希推 l_agent_chat 到远端并重启 → 端到端恢复
  （10.1s，`reasoning 47 / tool_start 1 / tool_result 1 / agent_reply 1`，0 错误）。
- ⚠️ **远端货架普遍落后**：每日 00:00 的 `auto upload <pkg>` 只做本机提交，**不推远端**；
  远端只有被手动推过的包是新的（本次推过 `l_log`/`l_nginx`/`lugwit_auth_client`/`l_agent_chat`），
  其余停在 10-02 前后 —— 排查远端怪问题时先比对包版本，别只信本机。
