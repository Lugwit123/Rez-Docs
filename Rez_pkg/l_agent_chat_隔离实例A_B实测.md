# l_agent_chat 隔离实例做 A/B 与计时实测（方法与坑）

> 什么时候需要：**对 `l_agent_chat` 做 A/B、或给"这轮为什么慢"归因**的时候。
> 宿主实例（`:1250`）带 `.dev_mod` —— 改一次源码就热重启一次，直接拿它做实验会踩两件事：
> ① 样本被连接重置掐断（**有并发 agent 在改包时尤其频繁**）；② 更糟的是，**两臂可能跑的不是
> 同一份代码**，结论看着有数据、其实无效。
> 配套采集器：`l_agent_chat/999.0/tools/iso_ab.py`。首次实测记录见 `l_agent_chat_改造记录.md` 第四部分。

## 1. 配方

另起一个实例：**独立端口 + 不带 `.dev_mod`（不随源码变）+ `.soloignore`**。它会绕开单实例守卫，
属规则 `.cursor/rules/service-lifecycle.mdc` §9 的「用户明确要求排障直启」豁免 —— 用完记得收。

```bat
:: iso_start.cmd（.cmd 必须 CRLF / 无 BOM / 仅 ASCII）
@echo off
set "AGENT_CHAT_PORT=1299"
set "AGENT_CHAT_WORKSPACE=E:\lugwit\trayapp\rez-package-source"
set "L_SVC_DIRECT=1"
cd /d e:\lugwit\trayapp
wuwor.bat l_agent_chat .soloignore -- python -m l_agent_chat.launcher > D:\Temp\lac_ab\iso.log 2>&1
```

`.soloignore` 会报 `已有实例运行 (pid=…)` —— 那是**预期**行为（不接管、只共存），不是失败。

就绪判据：`iso.log` 里出现 `自检通过: boot_id=…` 与 `[notepad] 预热完成`；再 `GET /health`。

## 2. 七个坑（都实测踩过）

| 坑 | 症状 | 解法 |
|---|---|---|
| **`%TEMP%` 会被清理** | 采集中途脚本与产物**整个消失**，traceback 都没有 | 产物与脚本放稳定目录（如 `D:\Temp\lac_ab\`），别放 `%TEMP%` |
| **`set "X=v && …"` 尾随空格** | `InvalidURL: Host '127.0.0.1:1299 ' contains invalid character ' '` | 用**引号式** `set "X=v"`；更稳的是把参数做成**命令行选项**（`--base`），别走环境变量 |
| **隔离 `LUGWIT_DATA_ROOT`** | 请求 200 但**零事件**；实例能起，模型侧直接失败 | 隔离数据根里**没有统一登录 token**（见下）→ 要么不隔离数据根（共用用户目录），要么把 token 一并带过去 |
| **后台任务的 job object 杀子进程** | 实例起来、能应答，**几秒~几分钟后无故消失**（日志无 traceback） | 把**实例 + 采集器放进同一条命令**，整棵树活到任务结束；或用 `Start-Process` 真脱离 |
| **`wuwor svc` 目标键前缀撞车** | `wuwo svc status l_agent_chat` → 「命中 2 张卡片」 | 目标键是**子串**匹配，`l_agent_chat` 被 `l_agent_chat_web_dev` 吃掉；改用 `wuwo svc list` 看状态 |
| **cmd 里 `python -c` 带中文** | 判断**恒为假**（`'验证不了' in d` 返回 False，让人以为改动没生效）；多行 `-c` 也会散架、静默什么都不输出 | 别在命令行传中文/多行：**写脚本文件**跑；要临时看字符串就**写到文件再用另一个进程读** |
| **脱离 wuwo 跑的工具会写到"另一棵树"** | 脚本改图/回滚**找不到文件**，或写进了服务看不见的地方 | `LUGWIT_DATA_ROOT` 是 **wuwo 注入**的实例数据根（`~/.lugwit/main`）；**裸 `py_312\python.exe` 跑**（没有它、也没有 `l_app_ready` 可 import）会走到 `flow_spec` 的兜底 → 曾经猜成共享层 `~/.lugwit/l_agent_chat/…`（**两棵树并存**）。**已在包侧修**（兜底改成"实例根存在就用"，与 `l_notepad_*` 同款）。但工具仍**别自己算**：要动"服务真正在读的那份"，就从**服务自报**的路径推（`GET /api/flow/status` 的 `source` 取父目录，`selfloop.shared_flows_dir()` 就是这么做的） |

第 3 条的原话（省得再猜）：

```
l_model_hub（http://127.0.0.1:8462）已启用统一登录闸门，但没取到 lugwit 登录 token。
请在设置页点「用 Lugwit 统一登录授权」…
```

所以**能共用数据根就共用**：会话会落在同一个 `sessions/<工作区 key>/`，采集器只建/删**自己的**会话，
用完不留痕。

## 3. 采集器用法

提示词实验开关是**运行期**的（`GET/POST /__dev__/prompt-flags`），所以四臂跑的是**同一份代码**，
差异只来自提示词 —— 这才能把效果从 LLM 波动里分出来。

```bat
:: 一条命令里起实例 + 跑矩阵（见坑 4）
wuwor l_agent_chat -- python tools/iso_ab.py --base http://127.0.0.1:1299 --out ab.jsonl all
:: 只看汇总（随时可看，按 (臂,题,样本) 断点续跑）
wuwor l_agent_chat -- python tools/iso_ab.py --out ab.jsonl
```

指标：总时长 / 规划步数 / 规划耗时 / 作答耗时 / 工具耗时 / 答案字数 / `path:line` 引用数 / 条目行数。
默认题集 2 道（文档型 + 定位型），臂 `A/B/C/D` = 两个开关的四种组合。

## 4. 判读约定（不守就白测）

- **同题内比**：`path:line` 引用数**跨题无意义**（"定位题"天然 30+ 处，"文档题"个位数）。
- **看中位数，不看单次**：同一臂同题的两次样本可以差 50%（实测 52.7s vs 80.7s），单次差异全是噪声。
- **先看方向是否在多个样本上一致**，再谈显著；n=2 只能给方向性结论。
- **工具耗时那一列噪声最大**（检索冷/热差 8s 量级），归因时别拿它当结论。
- 结论记进包内 `doc/CHANGELOG.md`（含"没复现"的那部分 —— 实测确实出现过「2 个非受控样本看着有效、
  受控复测无效」的情况）。

## 5. 自我优化的三道闸门（哪些改动走哪条）

「让 agent 优化自身」的形态是**取证 → 方案 → 实施 → 验证**，四步**必然交叉**（取证发现新问题、
验证失败回方案）。所以别当瀑布做，但要**拆两层循环**，否则没有收敛判据：

```
内层（便宜 / 自动 / 可反复跑）
  取证 ─→ 方案 ─→ optimize_agent verify（回放，验结构·路由）─→ apply
    ↑                                                      │ 备份 _versions/ + 回归默认拒收 + 留痕 _applied.jsonl
    └───────────── 发现新问题 / 报回归 ←───────────────────┘

外层（贵 / 有噪声 / 必须人拍板 / 一次一验）
  提示词·阈值类改动 → 起隔离实例（不带 .dev_mod，跑的是改后代码）
                    → 真采样 A/B（同题内比、看中位数）→ 结论落 CHANGELOG / 笔记
                    → 人决定宿主要不要重启吃下这次改动
```

### 按「改什么」选闸门

| 改什么 | 能在宿主里做吗 | 走哪条闸门 |
|---|---|---|
| **图 JSON**（`flows/*.json`）、笔记、记忆 | ✅ 能 —— 不是 `.py`，**不重启**，2s 热生效 | 内层（`verify` / `apply`），这是"边聊边改边验"唯一成立的类型 |
| 图**结构 / 路由**（加删节点、branch、门接线、`enabled`） | ✅ 能 | 内层（`verify` 回放**确定性**，够用） |
| **提示词 / 表达约束**（门 `params.prompt`、`_PLANNER_SYSTEM`、`ANSWER SHAPE`、RULES 注入） | ❌ | **外层**（回放放的是**旧提示词**的响应，验不了） |
| **阈值**（`read_repeat_limit`、`stall_reply_chars`、门 `max`） | ❌ | 先内层回放看"有没有把门弄死"，**效果仍要走外层** |
| 影响 payload 的默认值（如思考强度默认档） | ❌ | 外层 + 直测 |
| 缓存 / 预热 / 并发 / 性能 | ✅ 能 | **微基准 + 端到端计时**（不必做 A/B） |
| l_agent_chat 的 `.py`（`config.py`、提示词常量…） | ❌ | 外层；见下面「自指陷阱」 |

### ⚠️ 自指陷阱（最重要的一条）

**优化智能体就跑在宿主进程里。** 它去改宿主 `.py` → 宿主热重启 → **打死正在跑的这一轮，
也就是它自己**：方案、上下文、还没写完的 edits 全没（只留一条 `interrupted` 的半截回答）。

所以：

1. `optimize_agent` 的 `edits` **只接** `flow` / `note` / `memory` —— **没有"改源码"入口**。
   这个设计是**对的，别去扩**。
2. 改 `.py` 应该是**文件层面的动作**（人，或另一个会话），然后**另起隔离实例加载改后的代码**去验。
3. 隔离实例**不能改自己**（不带 `.dev_mod` → 改了不生效）—— 它只是"跑着新代码的靶子"。
4. `optimize_agent` 的取证只来自**本轮的 `_LAST_RUN` + 会话文件**，天生是「**本轮复盘**」；
   要**跨轮积累**（这类坑上次踩过）就走 `note` / `memory` 落盘，那不是它的职责。

### 三条边界（不守就失控）

1. **每轮留痕**：改了什么 + 判据（哪条用例 / 哪次 A/B）+ 结论（接受或回退）。
2. **外层不许自动循环**：16 次真调用 / ~20 分钟 / 真 token，且 n=2 只给方向 → 人拍板。
3. **真采样 A/B 不替代单测**：回归永远是先跑用例（快、免费），外层是最后一道闸门。

## 6. 编排器：进程外闭环（`tools/selfloop.py`）

### 为什么必须"进程外"

**闭环的锚点不能在被重启的那个进程里。** 优化智能体跑在宿主进程内，宿主一重启它就死 ——
所以它永远跨不过"落地"这一跳（这也正是 `optimize_agent` 的 `edits` **没有"改源码"入口**的原因，
那是有意的）。编排器在宿主外，负责发起与收尾，重启杀不死它。

| # | 步 | 谁做 | 关键点 |
|---|---|---|---|
| 0 | 取证 | 编排器 | 打宿主 API 读会话/trace，不依赖宿主内 agent |
| 1 | 提案 | agent（宿主内，无妨） | 产出提案 + **可核验判据** |
| 2 | **落副本** | 编排器 | `--stage <dir>` 把提案文件写进副本；**不碰共享** |
| 3 | **起隔离** | 编排器 | 新端口 + 不带 `.dev_mod` + **权限与真实一致**（见下） |
| 4 | 套验收 | 编排器 | `--tiers unit,endpoint,ab,equiv`（默认只 `unit`）；`equiv` = **录像回放**，现行图 vs 候选图各跑一遍同一句问题 |
| 5 | **拍板** | 规则式先判 → judge agent | 先核验提案自报的 `evidence`（**被证伪 → 直接 reject**）；再按 tiers 判；都能定音就不问模型；问模型时**必须回引数字**，引不出自动降级 `need_more` |
| 6 | 落地 | 编排器（**agent 无权**） | `--apply` 才落；先 `snapshot()` 备份 |
| 7 | 自检 | 编排器 | 等**空闲窗口**（`GET /api/runs/active`：跨会话没人在跑 **且** 没人在线）再重启；重启后 `/health.boot_id` 必须变 + `persist:false` 冒烟必须通 |
| 8 | 回滚 | 编排器 | 自检不过 → 从备份还原 + 再重启；全程记 `journal.jsonl` |

默认**只跑 2~5**（不落地、不重启）；`--apply` / `--restart` 是显式开关。

### 副本的三件必须事（实测踩出来的）

1. **src + `tests` 一起拷**。`run_all.py` 按**自己的位置**推 `../src`（`SRC = dirname(HERE)/src`），
   所以只有把 `tests` 放在副本的 `src` 旁边，验收才是对着**候选代码**跑的 ——
   否则拿真实包的用例去验候选，**跑绿了也说明不了候选没问题**。
2. **`iso_launch.py` 把副本 src 插到 `sys.path[0]`**（`import` 才会命中副本，而不是 rez 注入的共享 src）。
3. **环境要把"按 `__file__` 往上推"的路径钉回真实** —— 副本 src 会让这些全指错：
   `config._LUGWIT_ROOT` 直接算成 `None`（**启动就崩**，报
   `unsupported operand type(s) for /: 'NoneType' and 'str'`）。要显式给：
   `AGENT_CHAT_REZ_ROOTS`（`/rez` 浏览的两个仓库根）、`REZ_PACKAGE_SOURCE`（源码检索的根）。
   **这就是"沙箱与真实环境一致"的具体形态** —— 不是口号，是这几个环境变量。

### 实测证据（一次 `plan` + 一次真起隔离实例）

```
[副本] 覆盖 l_agent_chat/config.py（把 planner_batch_hint 默认 0 改成 1）+ 候选图
[隔离 :1299] config = {'planner_batch_hint': 1}      ← 跑的是副本代码
[宿主 :1250] config = {'planner_batch_hint': 0}      ← 共享**一点没动**
[隔离 flow]  source = D:\Temp\selfloop_test\iso\flows\default_intelligent_agent.json  ← 副本的图
```

### 用法

```bat
:: 只建副本 + 列清单（安全，不启服务、不碰共享）
wuwor l_agent_chat -- python tools/selfloop.py plan --flows <候选图.json> --stage <副本目录>

:: 走内层闸门：起隔离 → 跑验收 → 拍板（不落地）
wuwor l_agent_chat -- python tools/selfloop.py run --flows <候选图.json> --tiers unit,ab

:: 拍板通过才落地 + 等空闲窗口（没人在跑 + 没人在线）重启 + 自检（自检不过自动回滚）
wuwor l_agent_chat -- python tools/selfloop.py run --flows <候选图.json> --apply --restart
```

### 提案的主张怎么被核验（2026-10-07 补：真跑一次暴露出来的缺口）

一次真跑（"删图级重复键、纯图改动"）**链子全通** —— 副本 → 隔离 `:1299` → 副本里真跑 1012 个用例 236s
全绿 → 规则 → 对抗式 judge → journal → 收实例、共享一点没动 —— 但结论是 **`need_more`**，judge 的理由很硬：
**证据包里没有任何"等价性"证据**。根因不是模型苛刻，是**机器缺一块**：证据包只有
`tiers/overlaid/flows/criteria`，**提案自己的主张没有通道被核验** → "行为中性重构"这类提案在结构上
永远只能退人。补上两块：

- **`evidence`（可机器核验的自报证据）** —— 编排器**对着副本真验**，不信声明：
  - `{"claim","path","line"?,"contains"}`（文件 / 某行包含）
  - `{"claim","path","json_path","equals"|"absent"}`（JSON 值相等 / 不存在）
  - 相对路径解析顺序：**副本 → 工作目录 → 仓库根 → 包 src**；结果 `{checked,where,want,found}` 进证据包，
    逐条 `log` 打 ✔/✘；**被证伪 → `judge_rules` 直接 `reject`**（比"缺判据"更硬，不问模型）。
    行号别手填 —— 手填会被"文件长了几行"打脸（生成器里是**扫出来的**）。
- **`--tiers equiv`（行为等价档）** —— 走 `l_agent_chat.turn_replay`（录像取模型响应，plan/tools/护栏/
  收尾走真代码，不联网）：**现行图 vs 候选图各跑一遍同一句问题**，比 `steps/tools/gates/end` 与 `drift`，
  报告里的可引数字提上来进证据包。提案里可用 `"eq": {"cassette":"…","ask":"…"}` 声明。
  **没录像 / 没候选 / 找不到对照 → `ok=false` + 明确 `why`**：宁可退回人，也不假装验过。
  要真跑它得先有一盘**录像**（`<工作区>/.l_agent_ws/cassettes/<名>.jsonl`）。

### 还没做 / 需要你拍板的

- **`permissions` 把共享目录钉成 `deny`**（我上一轮说的"唯一能强制只改副本"的手段）**没有加**：
  它会连同你现在"边改边优化"的流程一起挡住（另一个 agent 就改不了包源码了）。
  要收紧的话，规则是：`<数据根>/l_agent_chat/flows` 与包 `src/` → `deny`，副本目录 → `allow`；
  编排器不受权限表约束，落地仍能做。
- ~~**`wait_idle` 只看当前会话**~~ **已修**（2026-10-07）：判据换成全局视图 `GET /api/runs/active`
  ——**跨会话**列出还没结束的轮次；老服务没有该端点时自动回退会话级（降级但仍可用）。
- ~~**`.py` 落地那一跳"没人在看"仍会被闪断**~~ **已处理**（2026-10-07）：同一个端点多报一个
  `clients`（前端在线数 = `/api/events` 的订阅者，页面开着就一直在）→ 编排器要求
  **没人在跑 且 没人在线** 才开窗口。代价是**刻意**的：主控页一直开着时 `clients > 0` 恒真 →
  永不自动重启，等于把"自动落地 `.py`"降级成"落盘 + 留痕"，重启时机交回给人。
  **等不到窗口时不再是"沉默失败"**：`wait_idle_detail()` 连原因一起返回（"2 个前端在线" /
  "1 个轮次在跑" / "状态未知"），`cmd_run` 打给人看 + 给出可照做的手动重启命令 + 落
  `journal` 一条 `step="restart_skipped"`（事后能查"这次改动为什么没生效"）。
- **架构级那条（"下一轮开始才用新代码"）评估后不做**：收益只是一次闪断，成本是把**进程内热替换**
  引入核心路径（模块级状态多：`config` 常量 import 时求值、工具注册表、`_RUNS`、SSE 长连接 →
  reload 会让新旧对象并存，是最难测的一类 bug）。

## 8. 追加探针（验证追加不覆盖）

> **本节是探针，不是新结论。** 目的只有一个：验证 `optimize_agent` 的 `note` 通道在**已有文档**上

### 三条教训（各一句）

1. **阈值 / 提示词类改动，沙箱回放验不了**：回放放的是**旧提示词**下录到的响应，改了就全 miss，
   只能标「需真采样验证」，真跑要走隔离实例做真采样 A/B。
2. **改图 / 落地要改「服务真正在读的那份」**：路径从**服务自报**（`GET /api/flow/status` 的 `source`）推，
   别自己算 —— 裸 python 跑会走到另一棵树（`~/.lugwit/l_agent_chat/flows` vs 实例数据根）。
3. **不许改 `tests/**` 迎合自己的改动**：把断言改成跟候选一致、删掉拦你的用例、或绕开工具直接改仓库，
   都**不算落地** —— 要如实报「没落地 + 为什么」。
