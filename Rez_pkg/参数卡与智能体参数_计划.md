## 一、口径（拍定的，别再改）

| 概念 | 定义 |
|---|---|
| **参数卡** | 一个节点（引擎类 `AgentParams`），一张卡 N 行参数，**行表**存进节点输入 `params`（JSON 文本，`hidden` 容器，浮层里编辑） |
| **一行的三态** | `literal` 写死在行里 / `port` 由**同名输入端口**喂（连了就用连线值，没连落 `value`）/ `param` **图的入参按名注入**（**不画线**） |
| **必传 vs 默认** | 行上的 `required`：解析出来是空 → **报错点名这一行**；不勾 → 用行里的 `value` 当默认值 |
| **端口** | **由行表推**：每行一个**输出**端口（名字 = 行名、顺序 = 行序）；`port` 行**多一个输入**端口。两处共用同一判据（引擎 `param_spec.rows_to_ports` / 前端 `pySchema.rowsToPorts`） |
| **谁优先** | **调用方（lagent / 工具调用）传的 > 卡里的默认值**。`param` 行既取"图的入参"，也取"调用方按名传的实参"——这两件事在 `graph.active_interface()` 这一层是**同一份** |
| **落到哪** | 卡的输出端口 = 每个参数的最终值 → 下游随便连（`HostStep` 的入参、`Preview`、别的节点都可以）；agent 侧也可以按名读走（同 `AgentPrompt` 的读法） |

协议只有一份，**两处必须同步改**：引擎 `l_node_engine/param_spec.py` ↔ 前端
`l_mindmap_mmd/web/src/pySchema.js`（`parseParamSpec` / `rowsToPorts` / `paramRowsToText`）。

## 四之二、2026-10-15：把**门阈值/文案**也收进参数卡（用户口径「哪些参数可以写到参数卡中，方便简化」）

**先定的三条口径**（写进代码注释了，改之前先读）：
1. 卡上的行**只有 `literal`（写死）/ `param`（图入参，调用方 > 卡）**两态能在 agent 侧解出来；
   `port` 态解不出（值在图内）—— 要它在 agent 侧也生效就得**连线**。
2. agent 侧**只认这 5 个键**：`model` / `provider` / `effort`（别名 `reasoning_effort`）/
   `thinking`（**布尔**）/ `max_steps`（夹 1..200，见 `app.py` 那段）；别的名字只会出现在
   `🎛 参数卡：…` 日志里，**不生效**。
3. **门读不到图接口**：`Gate` 的参数来自 resolved inputs（`gate_nodes.Gate.execute(**params)`）——
   图接口那套只有 `AgentParams` 自己读（`active_interface()`）⇒ 门的阈值/文案**只能连线喂**。

**做了的**：
- `pcards` 补两行：`provider`(str,param)、`thinking`(**bool** + `widget:checkbox`)。
  ⚠ `thinking` 必须是布尔 —— `_apply_thinking` 只认 `True`/`False` 两条分支，写 "off"/"low" 会静默无效。
- 新增**门参数卡** `gc`（`AgentParams`，摆在门链上方）6 行：
  `gate_hits`(int,2) · `fact_hits`(int,1) · `stall_nudge`/`fact_nudge`/`verify_nudge`/`confirm_nudge`(str,空)。
  · `gate_hits` **一行扇出**给 stall / verify / confirm / goal 四道门（一个旋钮管它们）；
  · `fact_hits` **单独一档**：`fact` 门在宿主侧的默认是 **1**（对齐硬编码那条护栏），跟 2 不是一回事，
    合成一个数就悄悄改了行为；
  · 文案行**默认空** = 用宿主那张门自己的默认提示词（行为与不接线**完全一样**），要改就在卡上写；
  · ⚠ `goal` 的文案**不搬**：它带 `{left}` 秒数格式化，搬成字面量就变成死文本。
- 阈值写 `0` = 用宿主默认；写数字 = **图上钉死**（卡片上现在写着 2 / 1，一眼看得见）。
- **`app.py` 一处口径修正**：`thinking` 只在**调用方真给了**（非 None）时才进 `overrides` ——
  以前固定传 `"thinking": thinking`，而 `agent_params` 的判据是"键在不在"，于是调用方没给
  （`None`）也会覆盖掉卡里那行 ⇒ 卡上的 `thinking` 永远轮不到。

**没做（写在清单里了，别当没提过）**：`p_sys/p_allow/p_deny` 三个提示词槽进卡
（`prompt_slots()` 的 `_literal_of()` 只做一跳解引用、认 `text/value/string/note/content`，
卡的值在 `params` JSON 列里 → 解不出来，要扩取值逻辑）；熔断阈值 `max_fails`、门默认拦次
`max_gate_hits`、空转提醒 `idle_after/idle_every`（都在 `TurnContext` 代码默认值里，图/app 都没读）
—— 要"一张卡调所有阈值"得 app 侧多喂几个键；`read_repeat_limit` 是全局设置，不是这张图的参数。

**自证（全绿）**：`l_agent_chat_gen_agent_asset --check` →「已经一致（33 个节点，新增 `gc`）」；
`tests.test_graph_turn` → **52 项 OK**（含 `AssetGuardTest`）；`l_agent_chat_graph_smoke` → **4/4**
（真图 + 真模型 + 真服务）；`l_agent_chat_graph_step_probe` → **PASS**；
`web_probe.cjs agentgraph` → **6/6**（节点 33 / 边 43 / 无孤立节点 —— 期望值是从资产现算的，
所以新加的 6 条连线自动进了判据）。

## 五、边界与坑

- **`port` 态在"发请求前"解不出来**：它的值来自图内上游节点 —— 想要它在 agent 侧生效，只能走
  "连到 `HostStep` 入参"那条路（P1 第 3 条）。
- **别把协议写成两份**：行表的键名改动必须同时改 `param_spec.py` 与 `pySchema.js`（两边都有注释指着对方）。
- **新增引擎节点后宿主不自动跟**：跑探针 / 编辑器验证前先 `wuwo svc reload l_mindmap_mmd_server`，
  否则 `/object_info` 里没有这个类，卡片会画成"未注册的节点类型"。
- **canvas 后端必须用节点自己那份元数据（`n.data.info`）算端口行**：这一轮踩到的真坑 ——
  `CanvasSurface` 的 `estimateSize` / `portRows` 原来读**静态** `object_info[classType]`，
  而端口表 / 参数表节点的端口是**就地推**的（静态那份是空的：`RETURN_TYPES = ()`）⇒
  canvas 后端上这些节点的**输出行一行都画不出来**（`PythonCode` 也一样，是存量 bug）。
  已修成 `infoOf(n, objectInfo)`（`data.info` 优先、静态那份当兜底）。判据 = 探针 `params` 的第 ⑤ 条。
- **`ALWAYS_RUN=True` 别去掉**：卡的值随调用方变，增量缓存会把上一轮的实参冻住。
- **权限类参数（permission）**：安全面，建议 UI 显式选择优先；要不要允许卡去设，等用户拍板。
