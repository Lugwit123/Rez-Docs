# 公网部署与增量同步

> 2026-10-01 实机走通后整理。适用：把本机 `trayapp` 树的改动推到公网服务器（Linux/Windows 均可的 Windows Server 2016+，**服务器上没有 E 盘、没有 `Lib/` 目录**）。
>
> 一句话：**走 `l_repo_sync_gui` 的直推通道 + 远端 sha256 逐文件比对**，只传内容变了的文件；**从不删除、从不重启**远端服务。

## 1. 通道是什么

| 项 | 值 |
| --- | --- |
| 通道实现 | `rez-package-source/l_repo_sync_gui/999.0/src/l_repo_sync_gui/deploy_channel.py` |
| 远端入口 | `http://121.196.144.88:8764`（= 服务器上的 `l_script_editor.standalone_server`）|
| 覆盖入口 | 环境变量 `DEPLOY_HOST`，或脚本参数 |
| 探活 | `GET /status` → 看 `editor_available: true`（`false` 时通道不可用，别硬试）|
| 鉴权 | `auth_requires: true` 但 `auth_scope: non_loopback` + `auth_ip_whitelist` 命中时**免 token**；本机 IP 已在白名单内 ✓ |
| 能力 | `POST /execute`（在宿主解释器里跑代码，**本机同名进程模块缓存会骗你**，验证要另起进程）、`/upload_folder`、`/download`、`/ui/*`（Qt 版 Playwright）|
| 现成脚本 | 每包一个 `deploy_*.py`（各自带 `TARGETS` 表 + `dry` 开关）；批量用本文第 3 节的 `deploy_to_public.py` |

**两条铁律**（`deploy_channel` 已固化）：

1. 上传一律 **base64 + `is_binary`** —— 否则纯文本会被写成 `\r\r\n`（CRLF 翻倍），行数翻倍、编译失败。
2. 写完必须 **sha256 全量比对**（`channel.hash_files()`）—— 不匹配就不能触发服务重启。

## 2. 增量：怎么做到"内容相同就不传"

`deploy_channel.collect_pkg_changes()` 优先用 `git status`；**本仓不是 git 仓库**（是 Depot），
于是它退化成 `mode == "full"`——**全量树**，会把几千个没变的文件重传一遍 ✗。

所以批量脚本改用通道自带的能力：

```python
channel.upload_files(remote_dir, files, skip_unchanged=True)
# 文档原文：先探测再上传 —— 逐文件比远端 sha256，只传 missing / mismatch 的，ok 的跳过
```

比"同大小 + 同日期"更严（**内容一致才跳过**）。2026-10-01 实测：`wuwo` + 21 个包共 12,092 个文件，
实传 1,238 个、跳过约 1,000+，`errors=0`；回扫全部 `需传 0`（等价 sha256 全量校验通过）。

**先探测后动手**：默认（不加 `--apply`）只打印「文件数 / 需传数」，一个字节都不写 ✓。

## 3. 批量 runner：`l_repo_sync_gui/999.0/deploy_to_public.py`

```cmd
cd /d E:\lugwit\trayapp
set PY=wuwo\py_312\python.exe

%PY% rez-package-source\l_repo_sync_gui\999.0\deploy_to_public.py
    :: 只探测：每个包"文件 N / 需传 M"，并列出差异文件名（默认目标 = wuwo + PKGS）

%PY% rez-package-source\l_repo_sync_gui\999.0\deploy_to_public.py --only wuwo --apply
    :: 真传：只传内容变了的；wuwo 里会跳过 config/config.yaml（见第 6 节）
```

- 树根默认 `E:\lugwit\trayapp`，可用环境变量 `LUGWIT_TRAYAPP` 换。
- `--host` / `DEPLOY_HOST` 换远端入口。
- **只传不删**：脚本不调 `delete_paths()`；**不重启**：不调 `restart_remote_service()`（8764 是我们的通道，自断后路最蠢 ✗）。
- 远端根写死为服务器的 `D:/TD_Depot/Software/Lugwit_syncPlug/lugwit_insapp/trayapp`。

## 4. 排除清单（本机运行时/私有数据，**绝不部署**）

| 排除项 | 为什么 |
| --- | --- |
| `__pycache__` `.git` `node_modules` `py_312` | 缓存 / 版本库 / 依赖 / 便携解释器（`Scripts/*.exe` shim 烤死本机路径，换机即废）|
| `logs_cache/` | `l_log` 的页面缓存，单文件几 MB，**还撑爆 413**（见下）|
| `upload_test/` | 测试产物 |
| `deploy_home.txt` | **部署级文件**：指定本机大件（模型权重）落盘位置，服务器上不该有 |
| `task_files.json` / `setting.yaml` | 本机专用配置（含本机绝对路径），服务器保留自己那份 ✓ |
| `wuwo/config/config.yaml` | 服务器数据根可能与本机不同（见第 6 节）✓ 单独补键 ✓ |
| `l_mindmap_fasthtml/data/` `.sesskey` | 本机脑图数据（私有）|

### 413：单请求体上限

`upload_files` 按**条数**分批，不按字节。一批里塞进多个 MB 级文件 → `HTTP Error 413: Request Entity Too Large`，
**整批失败**（其它文件不受影响，通道只报错不崩）。所以大缓存/大产物必须排除，或把 `--only` 拆细。

## 5. 服务器环境事实（本机没有的，容易踩）

| 事实 | 影响 |
| --- | --- |
| **没有 E 盘** | `wuwo/config/config.yaml` 里 `third_party` / `wowo_log_dir` / `l_shared_home_dir` 都是 E 盘绝对路径 —— 前两个**盘符缺失会自动回落**（`<trayapp>/rez-package-3rd`、`%LOCALAPPDATA%\Lugwit\logs\rez_pkg_log`），`LUGWIT_SHARED_HOME` **不注入**（包回落到实例目录）|
| **没有 `Lib/` 目录** | 树根探测不能要求同级有 `Lib/` ✗！必须 `wuwo/` 存在 **且**（`Lib/` **或** `rez-package-source/`）存在 —— 否则 `_LUGWIT_ROOT` 返回 `None`，87 个文件里的 `_LUGWIT_ROOT / '...'` 全部 `TypeError`（托盘 2026-10-01 已撞到过）|
| 数据根是**旧布局** `C:\Users\<用户>\.Lugwit\<包>` | 首次对接见第 6 节 |
| `~/.lugwit/instances.json` 原先不存在 | 说明服务器上的 wuwo 是**旧版**；推 `wuwo/` 之后才会创建 |
| 卡片是独立进程 | 传文件**不会**让它们换代码，要 `wuwo svc restart <别名>` |

## 6. 首次对接服务器数据根：**零搬移**

新 wuwo 会把用户数据算到「实例数据根」下；服务器数据本来就在 `~/.Lugwit/<包>`
→ 若直接覆盖它的 config，服务一重启就会去**空目录**写 ✗（表现为"数据看起来丢了"）。

正确姿势（2026-10-01 实机验证）：

1. 推 `wuwo` 时**跳过** `config/config.yaml`（runner 已内置 ✓）。
2. 只给服务器的 config **追加 3 行**（追加前先备份成 `config.yaml.bak_deploy` ✓）：

```yaml
instance: "srv"
data_root: "C:/Users/Administrator/.Lugwit"      # 指到**它现有的**数据根
l_data_dir: "{user}/.Lugwit/{pkg}"
```

3. **只读验证**（在宿主的 `/execute` 里跑，或另起子进程）：

```python
from l_app_ready.paths import pkg_data_dir
pkg_data_dir("lugwit_auth")   # 期望 = C:\Users\Administrator\.Lugwit\lugwit_auth（= 它现有的真目录）
```

实测结果一致 → 新旧代码解析到**同一个路径** ✓，零搬移 ✓。

## 7. 重启：谁和谁无关

服务器上 **8764（部署通道）与托盘是两条独立进程链**（实测 `共同祖先 = 空`）：

```
8764 ：python -m l_script_editor.standalone_server ← powershell(rez-shell) ← wuwo ← rez ← powershell -NoExit
托盘 ：ConEmuC64（标签 "/ROOT wuwor l_tray -- st"）← ConEmu.exe 窗口
```

- 重启托盘 **不会**影响 8764 ✓（可放心用 `wuwo svc`、或只结束托盘那条链再重跑 `wuwor l_tray -- st`）。
- ⚠️ 但**别关整个 ConEmu 窗口**（会连带关掉同窗口里别的标签，例如 Maya 的 `run_ui.bat`）；
  更别 `taskkill /T` 到根或 `/IM ConEmu*`。
- 在服务器上起 GUI 进程用 **参数列表 + `CREATE_NEW_CONSOLE` + stdout 落文件**（别在 `cmd /c "..."` 里手拼引号，
  会撞 `The filename, directory name, or volume label syntax is incorrect.`）；会话号要和登录桌面一致，
  否则进程活着但**托盘图标不显示**。

## 8. 回滚与安全网

- 改远端任何配置文件前先备份（本仓惯例：同名 + `.bak_deploy`）。
- 单包推进：`--only <包> --apply`，出错立刻停 ✓。
- 通道**从不删除**远端文件 → 最坏情况是留下多余文件，不会删数据 ✓。
- 上传后必做回扫（再跑一次不带 `--apply` 的探测）→ 期望 `需传 0`，否则说明写了但没写对 ✓。
